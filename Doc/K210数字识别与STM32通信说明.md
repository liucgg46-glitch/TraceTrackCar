# K210数字识别与STM32通信说明

## 1. 文档目的

本文用于说明送药小车项目中K210数字识别模块与STM32F407ZGT6主控之间已经通过测试的通信方案、代码位置、硬件接线、使用方法和注意事项。

当前已完成并验证的功能：

- K210能够稳定识别画面中的可变数量数字。
- K210按数字在画面中的横坐标从左到右排序。
- K210通过UART向STM32发送完整数字快照。
- STM32能够解析0个、1个、2个、3个、4个及更多数字，不会强制补足或裁剪成固定数量。
- STM32可以通过USART1向电脑输出通信状态和识别结果。
- K210可以脱离电脑和CanMV IDE，上电后自动运行识别程序。

以下功能不属于本模块已经完成的范围：

- 正式的送药任务状态机。
- 根据数字结果决定车辆停车、选择目标和执行路线动作的业务逻辑。
- STM32主动命令K210开始、停止或切换模式的双向控制。

当前稳定实现采用单向通信：

```text
K210识别数字 → UART发送快照 → STM32解析并缓存 → 测试任务输出日志
```

```text
        ↓
```

不要在UART中断或`bsp_uart.c`中直接判断数字、控制电机或执行送药任务。

## 3. 硬件接线

### 3.1 K210与STM32

当前K210识别程序配置：

```python
UART_TX_PIN = 6
UART_BAUDRATE = 115200
```

第一阶段使用单向通信：

| K210 | STM32F407ZGT6 | 说明 |
| --- | --- | --- |
| IO6 / UART1_TX | PA3 / USART2_RX | K210向STM32发送数字快照 |
| GND | GND | 必须共地 |
| K210 RX | 暂时不接 | 当前单向方案不接收STM32命令 |
| STM32 PA2 / USART2_TX | 暂时不接 | 当前单向方案不用 |

注意：仓库旧K210示例曾使用IO8作为TX，但该示例不是本次通过测试的运行版本。当前稳定识别脚本明确使用IO6，接线和排障必须以SD卡中的实际运行文件为准。

### 3.2 STM32调试串口

STM32使用USART1向电脑输出日志：

| STM32 | USB转TTL |
| --- | --- |
| PA9 / USART1_TX | RX |
| PA10 / USART1_RX | TX，可暂时不接 |
| GND | GND |

串口参数统一为：

```text
115200波特率
8数据位
无校验
1停止位
无硬件流控
```

USB转TTL必须使用3.3V逻辑。STM32、K210和USB转TTL必须共地。

### 3.3 供电注意事项

- K210应使用稳定且电流充足的电源。
- 不建议直接使用STM32开发板的3.3V引脚给K210供电。
- 可以让K210和STM32分别供电，但两者GND必须连接。
- 接线和拔线前应先断电，避免串口引脚带电插拔产生错误帧或损坏器件。

## 4. 通信协议

### 4.1 固定7字节底层帧

所有消息都使用固定7字节格式：

```text
[0] 0xAA
[1] 0x55
[2] CMD
[3] DATA1
[4] DATA2
[5] DATA3
[6] CHECKSUM
```

校验方式：

```text
CHECKSUM = 前6个字节累加和的低8位
```

即：

```c
checksum = (uint8_t)(
    frame[0] + frame[1] + frame[2] +
    frame[3] + frame[4] + frame[5]
);
```

### 4.2 可变数量数字快照

一次完整快照由以下帧组成：

```text
1个BEGIN帧
N个ITEM帧
1个END帧
```

总字节数：

```text
总字节数 = 14 + 7 × N
```

示例：

| 数字数量 | 总字节数 |
| ---: | ---: |
| 0 | 14 |
| 2 | 28 |
| 3 | 35 |
| 4 | 42 |

#### BEGIN帧

```text
AA 55 10 SEQUENCE COUNT STATUS CHECKSUM
```

| 字段 | 含义 |
| --- | --- |
| `SEQUENCE` | 快照序号，0～255循环 |
| `COUNT` | 本次快照中的数字数量 |
| `STATUS` | 本次识别状态 |

状态定义：

| 状态值 | 宏 | 含义 |
| ---: | --- | --- |
| 0 | `K210_RESULT_EMPTY` | 当前没有稳定数字 |
| 1 | `K210_RESULT_NORMAL` | 当前结果正常有效 |
| 2 | `K210_RESULT_AMBIGUOUS` | 当前结果存在歧义，不建议用于控制 |
| 3 | `K210_RESULT_OVERFLOW` | 数量超过通信缓存容量 |

#### ITEM帧

```text
AA 55 11 INDEX_DIGIT CONFIDENCE CENTER_X_8 CHECKSUM
```

`INDEX_DIGIT`的高4位为项目序号，低4位为数字类别：

```c
index = (INDEX_DIGIT >> 4) & 0x0F;
digit = INDEX_DIGIT & 0x0F;
```

其他字段：

| 字段 | 范围 | 含义 |
| --- | ---: | --- |
| `CONFIDENCE` | 0～100 | 识别置信度百分数 |
| `CENTER_X_8` | 0～255 | 压缩后的横坐标 |

STM32将横坐标恢复到QVGA的0～319范围：

```c
center_x = (((uint32_t)CENTER_X_8 * 319U) + 127U) / 255U;
```

#### END帧

```text
AA 55 12 SEQUENCE COUNT 00 CHECKSUM
```

STM32只有在以下条件全部满足时才提交快照：

- BEGIN和END的序号相同。
- BEGIN和END的数量相同。
- ITEM按照0、1、2……的顺序到达。
- 实际ITEM数量等于COUNT。
- 每个数字和置信度均在合法范围内。

### 4.3 数字数量原则

`K210_MAX_DIGITS = 8`只是STM32通信缓存容量，不是赛题逻辑要求。

识别结果：

- 不强制限制为1、2或4个。
- 不会为了符合预期数量而补足数字。
- 不会把多余数字静默裁剪掉。
- 当前画面中稳定看到几个数字，就发送几个数字。

K210已经按`center_x`从小到大排序，因此：

```c
snapshot.items[0]  /* 最左侧数字 */
snapshot.items[1]  /* 从左向右第二个数字 */
```

后续正式任务必须结合车辆状态、识别阶段和物理位置判断，不能只根据数量硬编码车辆动作。

## 5. STM32代码配置

### 5.1 通信初始化

`APP/app_all.c`已经调用：

```c
K210_Comm_Init();
```

不要在任务函数中重复初始化USART2或重复调用初始化函数。

### 5.2 数字识别通信测试任务表

测试数字识别通信时使用以下最小任务表，避免电机意外启动：

```c
Task_t task_list[] = {                                   \
    { Test_GPIO_Toggle,        10U, 0U },                \
    { AppTask_BSP_Background,   1U, 0U },                \
    { K210_Comm_Update,         5U, 0U },                \
    { Test_K210_CommUpdate,    10U, 0U },                \
};
```

两个任务作用不同：

| 任务 | 作用 |
| --- | --- |
| `K210_Comm_Update` | 从USART2取出字节、解析帧、组装快照，正式程序也必须保留 |
| `Test_K210_CommUpdate` | 通过USART1打印日志，只用于测试，正式业务任务表可以移除 |

顺序必须是先`K210_Comm_Update`，再由测试或业务任务读取结果。

任务列表宏续行注意事项：

- `Task_t task_list[] = {`和每个任务项行末尾都必须有反斜杠，结束行`};`不添加反斜杠。
- 反斜杠必须是该行最后一个字符，后面不能有空格或注释。
- 任务项需要注释时使用`/* 中文说明 */`，并把反斜杠放在块注释之后；不要使用会吞并下一续行的`//`注释。

### 5.3 正式运行任务表

正式运行时必须保留`K210_Comm_Update`任务，推荐周期为5 ms。测试通过后，正式业务任务表可以移除`Test_K210_CommUpdate`。送药业务逻辑实现后，应按源码中的实际函数名注册独立业务任务；在函数真正实现并经过安全测试前，不要把示意函数加入任务表。

### 5.4 USART1模式

使用USB转TTL调试时，`BSP/vehicle_config.h`必须选择：

```c
#define VEHICLE_UART1_LINK_MODE VEHICLE_UART1_LINK_DIRECT
```

不要同时把USB转TTL和E220的输出端并接到PA10。切换为E220模式后，USART1日志会进入E220链路，不应再按普通直连方式排查。

## 6. K210代码配置和自动启动

### 6.1 关键参数

当前识别脚本关键配置：

```python
MODEL_PATH = "/sd/projects/medicine_digit/model/model-293508.kmodel"
ENABLE_STM32_UART = True
UART_TX_PIN = 6
UART_BAUDRATE = 115200
OUTPUT_INTERVAL_MS = 200
```

不要只修改STM32端波特率或协议。两端的波特率、帧头、命令号、字段含义和校验方法必须一致。

### 6.2 SD卡根目录main.py

K210脱离电脑自动运行时，SD卡根目录的`main.py`应为：

```python
# -*- coding: utf-8 -*-

import gc
import time

time.sleep_ms(1500)
gc.collect()

print("AUTO START MEDICINE DIGIT")

exec(
    open(
        "/sd/projects/medicine_digit/model/"
        "digit_detect_stable_293508.py"
    ).read()
)
```

注意：

- 文件必须确实命名为`main.py`，不能是`main.py.txt`。
- `main.py`必须位于SD卡根目录。
- 上电后等待约3～5秒完成固件、摄像头和模型初始化。
- CanMV终端中的`print()`只用于USB调试；即使不连接电脑，`uart.write()`仍会通过IO6向STM32发送数据。


只看到`Build target`且耗时为0秒，可能只是复用了旧产物。必须检查`Objects/DroneProject.axf`的时间是否更新。

### 7.2 ST-Link烧录

烧录成功应显示：

```text
Erase Done.
Programming Done.
Verify OK.
```

在Flash Download设置中建议勾选：

```text
Erase Sectors
Program
Verify
Reset and Run
```

正常脱机启动要求：

- BOOT0接GND或保持低电平。
- 清除所有调试断点。

- 退出Keil甚至关闭电脑后，重新上电仍能运行。

如果只有进入Debug并点击Run后才执行，应检查`Reset and Run`、BOOT0和断点设置，而不是修改K210协议代码。

## 8. 日志含义

示例：

```text
K210 SNAP seq=103 status=1 count=2 [0]=5/80/x100 [1]=3/71/x173
```

含义：

| 字段 | 含义 |
| --- | --- |
| `seq=103` | 快照序号为103 |
| `status=1` | 正常有效结果 |
| `count=2` | 识别到2个稳定数字 |
| `[0]=5/80/x100` | 最左侧数字为5，置信度80%，中心横坐标100 |
| `[1]=3/71/x173` | 第二个数字为3，置信度71%，中心横坐标173 |

通信状态示例：

```text
K210 online=1 frames=1580 snapshots=450 check_err=1 format_err=0 snap_err=1 overwrite=0 last_rx=137994
```

| 字段 | 含义 |
| --- | --- |
| `online` | 1表示1秒内收到过有效帧，0表示超时离线 |
| `frames` | 累计收到的校验正确的7字节帧数 |
| `snapshots` | 累计成功提交的完整快照数量 |
| `check_err` | 校验错误帧累计数量 |
| `format_err` | 未定义命令或字段格式错误累计数量 |
| `snap_err` | 快照序号、数量、顺序或完整性错误累计数量 |
| `overwrite` | 上一份快照未读取就被新快照覆盖的累计数量 |
| `last_rx` | 最近一次有效帧到达时的系统毫秒计数 |

`check_err=1`或`snap_err=1`如果只在上电、复位或带电插拔时出现一次，之后不再增长，可以暂时接受。如果持续增长，应检查接地、供电、接线、波特率和协议版本。

## 9. 推荐验收流程

### 9.1 USART1单独测试

使用USB转TTL回环确认电脑、COM口和串口助手正常。然后只注册：

```c
Task_t task_list[] = { \
    { Test_GPIO_Toggle,        10U, 0U }, \
    { AppTask_BSP_Background,   1U, 0U }, \
    { Test_UART_Stats,        500U, 0U }, \
};
```

应周期输出：

```text
UART rx=0 tx=... ov=0 drop=0
```

### 9.2 K210通信测试

依次测试：

1. 不放数字，运行30秒。
2. 分别识别1～8。
3. 识别两个数字，检查左右顺序和横坐标。
4. 识别四个数字，例如5683。
5. 让数字从镜头边缘进入和离开，检查数量能够自然变化。
6. 连续运行至少5分钟。
7. 拔掉K210 TX，约1秒后应变为`online=0`。
8. 重新连接后应恢复为`online=1`。
9. K210脱离电脑，只保留供电，确认自动运行和UART输出。

验收目标：

```text
online=1
format_err=0
overwrite=0
check_err和snap_err不持续增长
识别数字及顺序与K210屏幕结果一致
```

## 10. 常见问题排查

| 现象 | 优先检查 |
| --- | --- |
| K210屏幕识别正常，STM32完全无日志 | STM32是否烧录并运行、USART1 DIRECT模式、PA9到TTL RX、共地、任务表 |
| STM32显示`online=0` | K210 IO6到STM32 PA3、两板共地、K210是否自动启动 |
| `format_err`持续增长 | K210和STM32不是同一套协议文件，混用了旧版单数字协议 |
| `check_err`持续增长 | 波特率不一致、接地不良、电源噪声、接线过长或松动 |
| `snap_err`持续增长 | BEGIN/ITEM/END丢帧、序号或数量不一致、串口干扰 |
| `overwrite`持续增长 | 业务任务读取快照太慢或没有调用`K210_Comm_GetNewSnapshot()` |
| 只能在Debug模式运行 | 清除断点、勾选Reset and Run、BOOT0接GND、重新烧录 |
| K210连接电脑能运行，脱机不运行 | SD根目录缺少正确`main.py`、路径错误、文件变成`.py.txt`、供电不足 |
| TTL回环收到`AB C1 23 45`和乱码 | 发送端使用了HEX模式而接收端使用ASCII显示，不一定是波特率错误 |

## 11. 后续正式业务代码建议

后续建议新增：

```text
APP/medicine_task.c
APP/medicine_task.h
```

正式任务不应直接操作K210底层帧，而应调用：

```c
K210_Comm_GetNewSnapshot(&snapshot);
K210_Comm_GetInfo(&info);
```

正式逻辑至少需要考虑：

- K210是否在线。
- 快照状态是否为`K210_RESULT_NORMAL`。
- 置信度是否达到业务要求。
- 当前车辆处于手持数字识别、双数字路口还是四数字区域。
- 数字正在进入或离开镜头时，数量会短暂变化。
- 车辆歪斜时，可能只看到部分目标，不能只凭单帧数量立即转向。
- 使用连续多帧确认，避免一次异常识别直接控制车辆。
- 识别结果超时后必须作废，不能无限使用旧快照。
- 通信离线时应进入安全状态，不能继续使用上一次数字控制车辆。

推荐的控制边界：

```text
K210负责：识别、去重、跨帧稳定、从左到右排序
STM32通信层负责：收帧、校验、组装、在线判断
送药任务层负责：结合任务阶段解释数字并决定车辆动作
底盘层负责：循迹、速度闭环、转向和停车执行
```

不要在`Test_K210_CommUpdate()`中加入正式车辆控制。测试函数只用于观察通信；正式决策必须放入独立的送药任务模块。

## 12. 验收结论

实际测试和串口日志已经验证：

- K210能够发送可变数量数字快照。
- STM32能够正确解析两数字和三数字快照。
- 数字、置信度和横坐标正确传输。
- `online=1`，协议格式错误为0，快照没有被覆盖。
- K210能够通过SD卡根目录`main.py`实现脱机自动运行。

因此，K210数字识别、快照发送以及STM32接收解析功能已经完成并通过测试。正式送药任务状态机，以及根据识别结果执行停车、目标选择和路线动作的控制逻辑，不属于本模块的完成结论。
