# 宏修改方法

> 本文按当前项目源码校正。当前 `Doc` 目录未发现对应的 Word 原文件；若后续恢复 Word 文件，必须同时检查本文和 `说明文档.md`。

## 一、切换 USART1 普通串口/E220 无线串口：BSP/vehicle_config.h

```c
#define VEHICLE_UART1_LINK_DIRECT           0U
#define VEHICLE_UART1_LINK_E220             1U
#ifndef VEHICLE_UART1_LINK_MODE
#define VEHICLE_UART1_LINK_MODE             VEHICLE_UART1_LINK_E220
#endif
```

- `VEHICLE_UART1_LINK_DIRECT`：USART1 保持普通直连串口，PA9/PA10 可接 USB-TTL 或其他 UART 设备，不使用 PE6。
- `VEHICLE_UART1_LINK_E220`：USART1 接 E220；PA9→E220 RXD、PA10←E220 TXD、PE6←E220 AUX。当前默认选择此模式。
- 两种模式都使用 `BSP/bsp_uart.h` 中 USART1 的 115200、8N1、无硬件流控配置。
- E220 透明传输模式还要求 M0、M1 均可靠接低电平，不能悬空；本项目没有用 MCU 控制 M0/M1。
- PE6 在当前源码中没有其他用途，但实际开发板是否已将 PE6 引出、是否与板载器件复用仍为“待确认”。
- 该宏选择的是同一组 PA9/PA10 的软件行为与外部接线。不要把 USB-TTL TX 和 E220 TXD 同时并接到 PA10；需要同时保留两套物理设备时，应增加硬件切换/隔离或改用另一组 UART。

### （一）E220 软件帧队列

E220 模式的软件帧队列在 `Driver/drv_e220.h` 配置：

```c
#define DRV_E220_TX_QUEUE_DEPTH          16U
#define DRV_E220_TX_FRAME_MAX_SIZE       512U
```

- AUX 忙、USART1 忙或 UART TX 空间不足时，`BSP_UART_WriteFrame()` 会保存整帧，`Drv_E220_Task()` 等 AUX 变高后重试。
- 队列深度越大，能吸收的短时拥塞越多，但默认每增加一帧约增加 512 字节 RAM；不能靠无限增大队列解决持续带宽不足。
- `DRV_E220_TX_FRAME_MAX_SIZE` 不得大于 `UART_TX_BUF_SIZE`。

路线测试数据已改到LCD/OLED，不再进入E220队列。需要两块屏同时显示时使用以下完整任务组合：

```c
Task_t task_list[] = { \
{ Test_GPIO_Toggle,        10U, 0U }, /* 运行指示灯 */ \
{ AppTask_BSP_Background,   1U, 0U }, /* BSP和Driver后台维护 */ \
{ Key_Update,              10U, 0U }, /* 按键扫描 */ \
{ Sensor_Update,            1U, 0U }, /* 传感器状态机 */ \
{ Encoder_Update,          10U, 0U }, /* 编码器测速 */ \
{ Test_RouteCmd_Update,    10U, 0U }, /* 路线测试按键 */ \
{ LineTrack_Update,        10U, 0U }, /* 路线与循迹 */ \
{ Motion_Update,           10U, 0U }, /* 动作推进 */ \
{ Chassis_Update,          10U, 0U }, /* 底盘速度控制 */ \
{ Test_RouteLog,          200U, 0U }, /* 激活路线调试页 */ \
{ LCD_Update,              20U, 0U }, /* LCD非阻塞刷新 */ \
{ OLED_Update,             20U, 0U }, /* OLED非阻塞刷新 */ \
};
```

`Test_RouteLog()`保留函数名用于兼容现有任务表示例，但只激活`ROUTE TEST`页面，不再发送USART1数据；`LCD_Update()`负责LCD约200 ms刷新，`OLED_Update()`负责OLED A/B两页自动切换。因此路线调试数据不会占用E220带宽。

## 二、修改车辆运动控制参数：Algorithm/control_config.h

所有底盘、循迹和动作控制调参宏统一放在 `Algorithm/control_config.h`：

- `CONTROL_CHASSIS_*`：底盘PWM前馈、车轮速度PI、目标斜坡、编码器安全保护和目标/输出限幅；
- `CONTROL_LINE_*`：灰度位置PD、加减速和丢线扫描；
- `CONTROL_MOTION_*`：直行/定角动作的容差、统一速度、越界回正速度、超时和转向比例；所有路线模式和测试入口共用，不再设置路线专用转弯速度。

不要再把参数复制到`APP/chassis.h`、`APP/motion_action.h`、`Algorithm/line_track.h`或`Route`文件中。灰度位置PD只生成上层`linear/turn`目标，底盘统一执行差速分配、PWM前馈和各驱动轮独立PI；外环与内环必须分别调节。

当前通过测试的底盘基线为：

```c
#define CONTROL_CHASSIS_SPEED_LOOP_ENABLE           1U
#define CONTROL_CHASSIS_PWM_MAX_PERMILLE           800
#define CONTROL_CHASSIS_TARGET_MAX_CPS             5000
#define CONTROL_CHASSIS_FEEDFORWARD_FULL_SPEED_CPS 5000
#define CONTROL_CHASSIS_SPEED_KP                    0.08f
#define CONTROL_CHASSIS_SPEED_KI                    0.002f
#define CONTROL_CHASSIS_SPEED_KD                    0.0f
#define CONTROL_CHASSIS_SPEED_INTEGRAL_LIMIT        20000.0f
#define CONTROL_CHASSIS_TARGET_SLEW_STEP_CPS        200
#define CONTROL_CHASSIS_ENCODER_FAULT_ENABLE        1U
#define CONTROL_CHASSIS_FAULT_MIN_TARGET_CPS        800
#define CONTROL_CHASSIS_FAULT_MIN_OUTPUT_PERMILLE   160
#define CONTROL_CHASSIS_FAULT_MAX_FEEDBACK_CPS      200
#define CONTROL_CHASSIS_NO_FEEDBACK_TIMEOUT_MS      500U
#define CONTROL_CHASSIS_DIRECTION_MIN_FEEDBACK_CPS  300
#define CONTROL_CHASSIS_DIRECTION_TIMEOUT_MS        500U
#define CONTROL_CHASSIS_FAULT_CLEAR_MAX_CPS         100
```

- `CONTROL_CHASSIS_SPEED_LOOP_ENABLE=1U`启用前馈＋PI；改成`0U`可临时退回固定前馈开环，用于标定和排障。
- `CONTROL_CHASSIS_TARGET_MAX_CPS`只限制上层目标；`CONTROL_CHASSIS_FEEDFORWARD_FULL_SPEED_CPS`只标定前馈比例，不要混用。
- 速度环按10 ms周期整定；改变`Chassis_Update`周期后必须重新调节`KI`，不能直接沿用当前值。
- 当前`KD=0`，编码器离散速度通常不需要微分。一次只改一个参数，先稳定车轮内环，再调整循迹PD。
- `CONTROL_CHASSIS_TARGET_SLEW_STEP_CPS`是每次`Chassis_Update()`允许的最大目标变化量；减小会更平滑但响应更慢，停车和急停不经过斜坡。
- 编码器故障保护只在`CONTROL_CHASSIS_SPEED_LOOP_ENABLE=1U`且`CONTROL_CHASSIS_ENCODER_FAULT_ENABLE=1U`时生效。正常使用不要为了绕过故障而关闭保护。
- 无反馈故障同时受目标、PWM、反馈和持续时间四类门槛约束；方向故障要求目标与PWM同向、反馈反向且达到最小反馈速度。调整任一门槛后必须重新进行断线、方向错误、正常低速和起步测试。
- 故障清除门槛由`CONTROL_CHASSIS_FAULT_CLEAR_MAX_CPS`控制。只有底盘已停止且所有启用车轮的原始速度都不超过该值，`Chassis_ClearFault()`才会成功。

编码器控制反馈的低通参数位于`Driver/drv_encoder.h`：

```c
#define DRV_ENCODER_SPEED_FILTER_ENABLE       1U
#define DRV_ENCODER_SPEED_FILTER_ALPHA_NUM    1L
#define DRV_ENCODER_SPEED_FILTER_ALPHA_DEN    4L
```

默认`1/4`已经通过当前速度环和循迹测试。改成`1/2`响应更快但噪声更明显，改成`1/6`更平滑但延迟更大。

传感器整体旋转180度后若循迹左右相反，只修改：

```c
#define CONTROL_LINE_DIRECTION_REVERSE 1U
```

正常安装方向使用`0U`。该宏会统一反转循迹误差、`black_mask`和左右分支类型，但不会倒序八路阈值。只改变安装朝向时，不要同时修改Driver中的`DRV_GRAY_MCU_INDEX_REVERSE`或`DRV_GRAY_4051_INDEX_REVERSE`；否则两层反向可能互相抵消。

各`CONTROL_*`宏的逐项用途、单位、调高/调低影响和推荐调试顺序，统一查阅`Doc/参数和引脚说明.md`第一、二节。2026-07-20已完成默认2WD车轮速度内环、目标斜坡、编码器故障保护和Basic循迹回归测试；进入后续动作库和新赛道调试时先冻结当前内环及安全门槛参数，避免同时修改内环和外层参数而无法判断问题来源。

### （一）修改五按键底盘速度测试目标：Driver/test.c

手动切回五按键底盘速度测试时，使用以下四个测试专用宏：

```c
#define TEST_CHASSIS_INITIAL_LINEAR_CPS  1600
#define TEST_CHASSIS_LINEAR_STEP_CPS      200
#define TEST_CHASSIS_LINEAR_MAX_CPS      4800
#define TEST_CHASSIS_TURN_CPS            1600
```

- `TEST_CHASSIS_INITIAL_LINEAR_CPS`：按 KEY1 时的前进速度，同时重置当前加速档位。
- `TEST_CHASSIS_LINEAR_STEP_CPS`：每次按 KEY2 增加的速度。
- `TEST_CHASSIS_LINEAR_MAX_CPS`：KEY2 可增加到的最大前进速度，不应超过 `CONTROL_CHASSIS_TARGET_MAX_CPS`。
- `TEST_CHASSIS_TURN_CPS`：KEY3/KEY4 原地转向时的转向速度绝对值。

这些宏只影响 `Test_ChassisCmd_Update()` 调试入口，不改变循迹、Route 或 Motion 的正式控制参数。

## 三、切换双路、四路驱动的宏：BSP/vehicle_config.h

```c
#define VEHICLE_DRIVE_MODE_2WD             2U
#define VEHICLE_DRIVE_MODE_4WD             4U
#ifndef VEHICLE_DRIVE_MODE
#define VEHICLE_DRIVE_MODE                 VEHICLE_DRIVE_MODE_2WD
```

说明：2WD 时 SPI1 可用于 LCD；4WD 时 PA6/PA7 被后编码器占用，当前代码会让 LCD 改用 SPI2，与 ICM-20948 共用总线。

建议：4WD 下在联合验证完成前，将 APP/lcd_ui.h 中的 LCD_UI_ENABLE 设为 0U，暂不使用 LCD。

## 五、修改灰度的 8 个默认值：Algorithm/line_detect.h

```c
#define LINE_DETECT_DEFAULT_THRESHOLD_0 1582
#define LINE_DETECT_DEFAULT_THRESHOLD_1 1662
#define LINE_DETECT_DEFAULT_THRESHOLD_2 2730
#define LINE_DETECT_DEFAULT_THRESHOLD_3 2385
#define LINE_DETECT_DEFAULT_THRESHOLD_4 2015
#define LINE_DETECT_DEFAULT_THRESHOLD_5 2425
#define LINE_DETECT_DEFAULT_THRESHOLD_6 2401
#define LINE_DETECT_DEFAULT_THRESHOLD_7 2449
```

注册`APP/line_calibration.c`中的`LineCalibration_Update()`时，KEY3会在已注册刷新任务的LCD/OLED显示新阈值，并从USART1输出八行带`U`后缀的宏。未注册该任务时两块屏都不显示校准页面。STM32不能直接修改电脑上的头文件；需要长期保留时，将串口输出复制到这里对应的`Algorithm/line_detect.h`。

八个阈值按Driver输出的物理通道保存。使用`CONTROL_LINE_DIRECTION_REVERSE`改变循迹方向时无需手工倒序；只有重新标定后才用新的串口输出覆盖这些宏。

## 六、启用 LCD：APP/lcd_ui.h

```c
#define LCD_UI_ENABLE                1U
#define LCD_UI_UPDATE_PERIOD_MS      200U
```

注意：要在任务循环中更新LCD，还需注册`LCD_Update`。建议以20 ms周期调用，10行页面采用非阻塞分步绘制；`LCD_UI_UPDATE_PERIOD_MS`为200 ms。`Test_ChassisCmd_Update()`激活底盘速度测试页，`Test_RouteLog()`激活路线测试页，`LineCalibration_Update()`激活校准页。路线测试页必须同时注册`Test_RouteLog`和`LCD_Update`，且不再发送USART1日志。

## 七、启用 OLED：Driver/drv_oled_i2c.h、APP/oled_ui.h

```c
#define DRV_OLED_I2C_ENABLE          1U
#define OLED_UI_ENABLE               1U
```

注意：要在任务循环中更新OLED，还需在`APP/app_task_config.h`中注册`OLED_Update`。`Test_RouteLog()`激活A/B自动切换路线页，`LineCalibration_Update()`激活标定页；只有业务激活任务和`OLED_Update`同时注册时才显示对应专用页面。
