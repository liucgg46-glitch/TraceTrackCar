# STM32F407原工程工程说明

## 1. 工程目标

该工程用于非阻塞循迹小车，包含电机与编码器、底盘闭环、Yahboom 8路串口灰度循迹、动作库、路线规则、整车任务状态机、ICM20948、VL53L1X、HX711、LCD/OLED、K210 和 E220。

## 2. 分层

| 层级 | 作用 |
| --- | --- |
| `Common` | 平台无关状态码和临界区抽象 |
| `BSP` | 芯片外设、引脚、中断、DMA、时基 |
| `Driver` | 器件驱动 |
| `Algorithm` | PID、通用循迹、姿态、里程、钢球状态估计与状态反馈 |
| `Route` | 赛道巡线规则、路段事件和路线控制意图 |
| `APP` | 底盘仲裁、动作、传感器管理、显示和整车任务状态机 |
| `Test` | 专项测试入口，不进入封箱正式任务表 |

```text
APP整车任务状态机
        ↓ 启停与任务目标
Route赛道巡线规则
        ↓ 控制意图
Algorithm / Driver
        ↓
BSP
        ↓
STM32F407ZG
```

`APP/task_profile_*`负责整车从等待、启动、运行到完成或故障的业务流程；`Route/route_profile_*`只负责具体赛道如何巡线、何时转弯以及何时上报到达。两者不能混为同一层。

## 3. 启动流程

```text
BSP_InitAll()
→ Driver_Init()
→ App_Init()
→ TaskProfile_Init()
→ Scheduler_Init()
→ Scheduler_Run()
```

## 4. 两个独立选择入口

| 配置 | 文件 | 当前选择 |
| --- | --- | --- |
| 整车任务状态机 | `APP/task_profile_config.h` | `TASK_PROFILE_H2_ROUND_STOP` |
| 赛道方案 | `Route/route_config.h` | `ROUTE_PROFILE_H_OVAL` |

H题顶层状态机内部由`H_COMPETITION_ITEM_SELECT`选择比赛子流程，当前选择
`H_COMPETITION_ITEM_BALL_SEQUENCE`。任务3的O点、+50 mm、-50 mm顺序直接作为
该顶层状态机子状态运行，不存在第二个并行比赛状态机。选择层仍会检查整车任务
与Route方案是否匹配。

其他配置入口：

| 配置 | 文件 |
| --- | --- |
| 静态任务表 | `APP/app_task_config.h` |
| 专项测试开关 | `Test/test_config.h` |
| 底盘与链路模式 | `BSP/vehicle_config.h` |
| 控制参数 | `Algorithm/control_config.h` |
| 钢球控制参数 | `Algorithm/ball_balance_config.h` |
| 灰度来源 | `Driver/drv_gray_sensor.h` |

当前默认灰度来源为`GRAY_SENSOR_SOURCE_YAHBOOM_UART`，使用USART3的`PD8/PD9`
读取Yahboom 8路灰度模块串口数字量。Driver保留模块真实0/1到`raw`，并把
`filt`统一映射为黑线0、白底4095，上层继续按`filt < threshold`判断黑线。

数字量基础循迹链路已经固定为：

```text
Yahboom数字帧
→ gray filt与black mask
→ LineDetect离散位置误差
→ LineTrack 1/2误差滤波与P/PD
→ RouteManager控制意图
→ Chassis左右轮目标、目标斜坡和速度PI
→ Motor PWM
```

`LineTrack`包含`TRACK`、`LOST_CONFIRM`、`SEARCH`和`FAILSAFE`。连续两帧丢线
进入向前搜索，搜索时不再把线速度置零；重新看到线路的首帧立即恢复误差修正，
连续三帧确认后回到`TRACK`。搜索期间内侧轮上层目标最低为800 cps。

STM32工程使用`DroneProject.uvprojx`；新增固件`.c`时同步更新Keil工程和Makefile。

## 5. 基础循迹与状态机注册

基础循迹和当前H题第2项共用以下正式注册函数：

| 注册函数 | 周期 | 责任 |
| --- | --- | --- |
| `Sensor_Update` | 1 ms | 推进灰度Driver并更新传感器缓存 |
| `Encoder_Update` | 10 ms | 更新车轮速度反馈 |
| `TaskProfile_Update` | 10 ms | 推进当前选择的整车任务状态机 |
| `LineTrack_Update` | 10 ms | LineDetect、RouteManager和LineTrack |
| `Motion_Update` | 10 ms | 推进Route请求的非阻塞动作 |
| `Chassis_Update` | 10 ms | 目标斜坡、速度PI和PWM输出 |
| `LCD_Update` | 20 ms | 异步状态页面 |

当前`PROJECT_TEST_TASKS_ENABLE=0U`，正式任务表用于H题第3项静止滚球，不注册
底盘、循迹和电机控制任务。`K210_Comm_Update()`和
`BallBalance_K210Adapter_Update()`提供视觉样本，`BallBalance_App_Update()`
负责控制安全，`TaskProfile_Update()`只推进O→+50 mm→-50 mm比赛流程。

钢球控制链为：K210位置→VALID/HOLD/LOST管理→位置/速度/等效扰动三状态卡尔曼
估计→限速度/加速度/加加速度参考→位置速度状态反馈→局部平衡角表→静摩擦补偿
→舵机绝对限位和变化率限制→PF8舵机。底盘IMU前馈适配接口已建立，但当前工程
没有可靠的去重力线性加速度缓存，因此默认关闭且输出无效。

## 6. B题基础巡线结构

- `APP/task_profile_b_basic.c/.h`：KEY1启动、KEY4停止、运行监控、故障停车、到达鸣笛；
- `Route/route_profile_b_basic.c/.h`：直角、虚线、三角尖头和终点停止线；
- `Algorithm/line_track.c`：普通路段PD循迹；
- `APP/line_follow_app.c`：Route控制意图与底盘控制权之间的通用适配，不承担蜂鸣器和整车完成流程。

正式任务表不包含任何`Test_*`函数。详细参数和测试方法见`Doc/B题基础巡线说明.md`。

## 7. 周期建议

- 1 ms：后台和传感器状态机；
- 5 ms：K210解析，仅视觉任务使用；
- 10 ms：按键、编码器、整车状态机、底盘、动作、巡线；
- 20～100 ms：显示任务；
- 200～500 ms：调试日志，封箱版本可不注册。
