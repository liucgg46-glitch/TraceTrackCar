# STM32F407工程测试任务完整手册

> 本文以当前工作区源码为准，并作为测试入口、任务注册、操作步骤、输出和
> 通过标准的唯一测试手册，不再另外维护重复的“测试任务注册函数”文档。

## 0. 使用前必须完成

1. 工程只有`APP/app_task_config.h`中的一个直接任务列表，不使用任务档位宏。
2. 从本文复制一个完整`task_list[]`替换该列表，不从不同章节抽行拼接。
3. 测试任务需要的头文件也只在`APP/app_task_config.h`中按实际任务包含。
4. `Test/test.c`和`Test/test_k210_comm.c`均已进入Keil与Makefile。
5. 最终封箱时由项目负责人把该唯一列表替换为最终正式任务。

### 统一规则

- `Test/test.h`是所有公共`Test_*`测试入口的唯一依据；`static`辅助函数不得
  写入任务表。
- 除 GPIO 专项外，运行心跳统一使用 `AppDiagnostics_HeartbeatUpdate()`。
- `Test_GPIO_Toggle()`只用于 GPIO 专项，不再充当其他测试的运行指示。
- `AppTask_BSP_Background()`必须保留。
- 按键任务顺序：`Key_Update()`在消费事件的任务之前。
- 传感器任务顺序：`Sensor_Update()`在读取缓存的测试之前。
- 底盘任务顺序：`Encoder_Update()`在 `Chassis_Update()`之前。
- 同时只能有一个任务控制电机或显示页面。

## 1. BSP 普通 GPIO 翻转测试

**对应入口：**`Test_GPIO_Toggle`

### 可直接复制的完整任务表

```c
Task_t task_list[] = {
    { AppTask_BSP_Background, 1U, 0U }, /* 后台维护 */
    { Test_GPIO_Toggle, 10U, 0U }, /* 测试 BSP_GPIO_CH1 */
};
const uint8_t TASK_NUM =
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

`Test_GPIO_Toggle()`每 500 ms 翻转一次 `PC13 / BSP_GPIO_CH1`。本项不要再注册
`AppDiagnostics_HeartbeatUpdate()`，因为两者控制同一个逻辑 GPIO，同时翻转会导致现象混乱。

**通过标准：**对应 LED 或测试引脚稳定以约 1 Hz 的亮灭周期变化。

## 2. 红绿状态灯循环测试

**对应入口：**`Test_StatusLight_Update`

### 可直接复制的完整任务表

```c
Task_t task_list[] = {
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */
    { AppTask_BSP_Background, 1U, 0U }, /* UART、总线和异步驱动后台 */
    { Test_StatusLight_Update, 10U, 0U }, /* 红、绿、灭循环 */
};
const uint8_t TASK_NUM =
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

该任务按“红灯 1 秒 → 绿灯 1 秒 → 全灭 1 秒”循环，不读取按键或串口。

**通过标准：**三种状态顺序固定，红绿灯不会同时点亮。

## 3. 蜂鸣器按键测试

**对应入口：**`Test_Buzzer_Update`

### 可直接复制的完整任务表

```c
Task_t task_list[] = {
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */
    { AppTask_BSP_Background, 1U, 0U }, /* UART、总线和异步驱动后台 */
    { Key_Update, 10U, 0U }, /* 按键扫描与消抖 */
    { Test_Buzzer_Update, 10U, 0U }, /* 蜂鸣器控制 */
};
const uint8_t TASK_NUM =
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

当前蜂鸣器接在`PG7`，按低电平有效配置。按键行为如下：

| 按键 | 行为 |
| --- | --- |
| KEY1（PE4） | 按下一次后持续鸣响；稳定按住也能触发，避免按下边沿被清除后无响应 |
| KEY2（PE3） | 进入间歇鸣响模式，每500 ms翻转一次 |
| KEY3（PE2） | 立即停止；同一轮多个按键触发时停止优先 |
| KEY4、KEY5 | 不使用 |

上电后任务会先等待KEY1～KEY3全部稳定松开约100 ms，再接受控制。测试结束前按KEY3确认关闭。该函数不发送串口日志。
## 4. PWM 占空比渐变测试

**对应入口：**`Test_PWM_Ramp`

## 5. BSP 编码器原始日志

**对应入口：**`Test_Encoder_Log`

### 可直接复制的完整任务表

```c
Task_t task_list[] = {
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */
    { AppTask_BSP_Background, 1U, 0U }, /* UART、总线和异步驱动后台 */
    { Encoder_Update, 10U, 0U }, /* 更新编码器速度 */
    { Test_Encoder_Log, 200U, 0U }, /* 输出 BSP CH1/CH2 */
};
const uint8_t TASK_NUM =
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

USART1 调试串口每 200 ms 输出：

```text
ENC L: d=... cps=... total=... | R: d=... cps=... total=...
```

`d`是本周期增量，`cps`是每秒计数，`total`是累计计数。静止时 `d/cps`应接近 0。

## 7. 编码器每圈计数测试

**对应入口：**`Test_CountPerRev_Update`

### 可直接复制的完整任务表

```c
Task_t task_list[] = {
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */
    { AppTask_BSP_Background, 1U, 0U }, /* UART、总线和异步驱动后台 */
    { Encoder_Update, 10U, 0U }, /* 更新累计计数 */
    { Test_CountPerRev_Update, 10U, 0U }, /* 接收 c/p 命令 */
    { Test_DrvEncoder_Log, 200U, 0U }, /* 同时观察速度方向 */
};
const uint8_t TASK_NUM =
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

通过USART1 调试串口发送：

| 命令 | 行为 |
| --- | --- |
| `c` 或 `C` | 清零累计计数，输出 `encoder total cleared` |
| `p` 或 `P` | 输出 `TOTAL FL=... FR=... RL=... RR=...` |

流程：悬空车轮 → `c` → 手动转动目标轮一整圈 → `p`。重复三次，取绝对计数平均值。

## 16. 底盘速度闭环按键测试

**对应入口：**`Test_ChassisCmd_Update`、`Test_ChassisCmd_Log`

### 可直接复制的完整任务表

```c
Task_t task_list[] = {
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */
    { AppTask_BSP_Background, 1U, 0U }, /* UART、总线和异步驱动后台 */
    { Key_Update, 10U, 0U }, /* 按键扫描 */
    { Encoder_Update, 10U, 0U }, /* 必须先于底盘 */
    { Test_ChassisCmd_Update, 10U, 0U }, /* 按键速度命令 */
    { Chassis_Update, 10U, 0U }, /* 前馈和速度 PI */
    { LCD_Update, 20U, 0U }, /* 底盘测试页面 */
    { Test_ChassisCmd_Log, 200U, 0U }, /* 完整闭环日志 */
};
const uint8_t TASK_NUM =
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

| 按键 | 行为 |
| --- | --- |
| KEY1（PE4） | 1600 cps 前进，并重置加速档位 |
| KEY2（PE3） | 每次 +200 cps，最高 4800 cps；必须先按 KEY1 |
| KEY3（PE2） | 原地左转，turn=+1600 cps |
| KEY4（PE1） | 原地右转，turn=-1600 cps |
| KEY5（PA15） | 急停并尝试清除故障 |

日志以 `CHS loop=... fault=... mask=... cmd=... tgt=... raw=... fb=... ff=... pi=... out=...`开头。
所有启用车轮反馈符号应与目标一致，正常时 `fault=0`。

    { Key_Update, 10U, 0U }, /* 按键扫描 */
    { Encoder_Update, 10U, 0U }, /* 编码器测速 */
    { Test_ChassisWatchdog_Update, 10U, 0U }, /* 只发送一次速度命令 */

通过USART1 调试串口发送：

| 命令 | 行为 |
| --- | --- |
| `1`、`l`、`L` | 启动循迹 |
| `0` 或 `x` | 停止并停车 |
| `w` | 记录当前 8 路值为白底 |
| `b` | 记录当前 8 路值为黑线 |
| `t` | 生成 8 路阈值 |
| `d` | 恢复默认阈值 |
| `p` | 立即打印 RAW/FILT/TH/mask/error/type/output |
| `k` | 扫描 I2C |

发送`1`启动即可。`w`、`b`和`t`仅保留给模拟量兼容模式。

当前默认灰度来源为Yahboom 8路串口灰度模块数字量模式，使用USART3：
模块`RX`接`PD8/USART3_TX`，模块`TX`接`PD9/USART3_RX`，5V供电并与主控
共地，串口参数115200 8N1。上电约3秒且连续收到有效数字帧后判断在线。

白底应表现为`RAW=1/FILT=4095`、`mask=0x00`、`type=LOST`；黑线通道
应表现为`RAW=0/FILT=0`并进入`mask`。全部探头压黑线时可出现
`mask=0xFF`、`type=FULL`。

**对应入口：**`Test_ServoBeamCalibration_Update`

### 37.1 输出位置和串口接线

本测试不注册`LCD_Update()`，所以LCD不会显示脉宽。所有提示只输出到USART1：

- STM32 `PA9/USART1_TX`连接USB-TTL的RX；
- STM32 GND连接USB-TTL的GND；
- 本测试不接收电脑命令，PA10可以不接；需要双向通信时再把PA10接USB-TTL TX；
- 串口助手选择115200、8位数据位、1位停止位、无校验、无流控；
- USB-TTL的VCC不要连接舵机电源。

工程当前`BSP/vehicle_config.h`默认把USART1配置为E220链路。如果使用USB-TTL
直接看电脑串口，先改成：

```c
#define VEHICLE_UART1_LINK_MODE             VEHICLE_UART1_LINK_DIRECT
```

然后重新编译、烧录。如果保持`VEHICLE_UART1_LINK_E220`，这些文本会从E220
链路发出，且PE6的AUX状态可能影响发送，不能把它当作普通USB-TTL直连模式。

### 37.2 舵机和机械接线

- PF8/TIM13_CH1连接WHEELTEC S20F信号线；
- 舵机使用符合自身额定电压的独立BEC，BEC地与STM32地共地；
- PF9俯仰舵机本次不接；
- 第一次上电前取下钢球，使车轮离地，并确认齿条处于机械中间附近；
- 不允许用STM32板载电源直接给舵机供电。

### 37.3 实际测试顺序

1. 确认唯一任务表已替换为本节列表，按37.1连接串口并烧录。
2. 先接通STM32和串口，再接通舵机BEC。上电会立即输出0度。
3. 串口应首先出现：

```text
[ServoCal] range=0..180deg pulse=500..2500us step=10deg
[ServoCal] KEY1=0deg KEY2=180deg KEY3=+10deg KEY4=-10deg
[ServoCal] KEY5=stop/0deg
[ServoCal] angle=0deg pulse=500us command=INIT_0DEG status=OK
```

4. KEY1立即输出0度；KEY2立即输出180度；KEY3每次增加10度；KEY4每次减少10度；
   KEY5立即停底盘并回到0度。
5. 每次按键后串口会输出`angle=...deg pulse=...us command=... status=OK`。
   如果角度变化但舵机仍完全不动，优先查PF8波形、舵机信号线顺序和共地。
6. 普通万用表量PF8信号线看到约0.1V到0.5V是正常的平均值现象，不能证明没有PWM。
   需要用示波器、逻辑分析仪或舵机测试器确认PF8是否为50Hz、约500到2500us高电平。
7. 第一次做0度和180度全行程动作时必须取下钢球、车轮离地，手靠近舵机电源开关。
   一旦齿条撞端、异响、抖动或堵转，立即按KEY5或断开舵机电源。
8. 记录0度、90度、180度对应的实际摆杆方向，以及哪一端会接近机械干涉。

本测试不自动扫描、不注册底盘、循迹、传感器或显示任务。

### 37.4 现象、原因和该改哪里

| 现象 | 首先检查 | 需要修改 |
| --- | --- | --- |
| LCD没有数据 | 这是正常现象，本测试只看USART1 | 不改LCD代码 |
| 串口完全无输出 | USART1是否为DIRECT、TX/RX是否交叉、是否共地、是否115200 8N1 | USB-TTL测试时修改`VEHICLE_UART1_LINK_MODE`并重新编译 |
| 有输出且`status=OK`，角度和脉宽变化但舵机不动 | BEC电压、BEC与STM32共地、PF8信号线顺序、舵机是否损坏、机构是否卡死 | 先用示波器/逻辑分析仪/舵机测试器确认50Hz PWM，再决定是否改代码 |
| 输出`status=ERROR` | PF8 PWM初始化或TIM13资源异常 | 检查BSP PWM配置和初始化，不扩大限位 |
| PF8用万用表量约0.35V | 50Hz舵机PWM占空比较低，万用表显示的是平均电压 | 不按万用表直流电压判断信号是否正常 |
| 0度或180度撞端、异响、堵转 | 舵机标称全行程超过齿条机械行程 | 立即KEY5/断电，把Driver水平脉宽边界收回到安全端点 |
| 90度不是机械水平 | 齿轮装配初始位置或中心脉宽不匹配 | 验证后修改`SERVO_HORIZONTAL_CENTER_US`或重新装齿轮中心 |
| 角度增减方向与预想相反 | 齿轮、齿条安装方向不同 | 先记录真实方向；最终控制映射确认后再调整上层方向 |
| 每次10度太大 | 机械传动比大或接近端点 | 把`TEST_SERVO_CAL_STEP_ANGLE_DEG`改为5、2或1 |

当前标定参数位置：

- `Driver/drv_servo.c`：
  `SERVO_HORIZONTAL_RIGHT_LIMIT_US`、`SERVO_HORIZONTAL_CENTER_US`、
  `SERVO_HORIZONTAL_LEFT_LIMIT_US`，当前为500、1500、2500us；
- `Driver/drv_servo.c`：
  `SERVO_HORIZONTAL_MIN_ANGLE_DEG`和`SERVO_HORIZONTAL_MAX_ANGLE_DEG`，
  当前角度范围为0到180度；
- `Test/test.c`：
  `TEST_SERVO_CAL_STEP_ANGLE_DEG`只控制KEY3/KEY4每次变化多少度。

完成实测后，把不会撞端的实际安全脉宽范围写回Driver水平限位；如果继续做比赛闭环，
上层建议使用角度或归一化位置，不要绕过Driver直接写BSP PWM。

完成标定后，将`APP/app_task_config.h`替换为下一阶段所需的唯一任务列表；
如果为USB-TTL测试临时改过USART1链路，也按实际硬件恢复E220或保留DIRECT，
然后重新编译。

## 41. K210传统灰度钢球现场调参

**对应入口：**`Test_K210_GrayTuneUpdate`

该入口只发送传统灰度视觉的现场调参命令，不读取或清除0x32钢球新帧，因此
可以与纯通信日志任务同时注册：

```c
Task_t task_list[] = {
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */
    { AppTask_BSP_Background, 1U, 0U }, /* UART后台 */
    { K210_Comm_Update, 5U, 0U }, /* 解析K210钢球帧 */
    { Key_Update, 10U, 0U }, /* KEY6至KEY9扫描 */
    { Test_K210_GrayTuneUpdate, 20U, 0U }, /* 传统灰度参数调节 */
    { Test_K210_BallCommUpdate, 10U, 0U }, /* 纯通信日志 */
};
const uint8_t TASK_NUM =
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

KEY6切换正常/二值画面，KEY7循环选择`BALL_MIN`、`BALL_MAX`、`PIPE_MIN`、
`PIPE_MAX`，KEY8增加5，KEY9减少5。该测试不改变0x32协议、位置单位或
VALID/HOLD/LOST定义。

## 42. 其他公共可调度入口

下面列出源码公共头文件中尚未在前述专项任务表单独说明、但函数签名允许直接
加入`APP/app_task_config.h`唯一任务列表的入口。此表用于查找入口，不表示这些
任务应当同时注册；同一硬件或同一业务链路存在封装关系时，应只注册推荐的上层
入口，避免重复更新。

| 任务入口 | 用途与注册注意事项 |
|---|---|
| `AppOdometer_Update` | 更新APP里程计适配缓存；若已有包含同类更新的上层任务，不要重复注册。 |
| `BTask_Update` | B题业务状态机入口；与其他整车顶层状态机按项目阶段择一注册。 |
| `DebugMenu_Update` | 调试菜单刷新入口；需要菜单交互时注册。 |
| `Driver_Task` | Driver聚合后台入口；与`AppTask_BSP_Background`职责重叠时不要同时注册。 |
| `Drv_Buzzer_Toggle` | 蜂鸣器翻转入口；仅用于需要固定周期鸣叫的专项任务。 |
| `Drv_E220_Task` | E220驱动后台处理；通常由板级或Driver聚合后台间接调用。 |
| `Drv_Encoder_Update` | 编码器驱动直接更新；正式业务优先注册`Encoder_Update`。 |
| `Drv_Gray4051_Update` | 4051灰度采集直接更新；只在绕过传感器管理层的专项测试中使用。 |
| `Drv_Laser_Task` | 激光器驱动后台处理；通常由聚合后台间接调用。 |
| `Drv_LcdTft_Task` | LCD驱动底层刷新；正式业务优先注册`LCD_Update`，不要重复刷新。 |
| `Drv_OledI2c_Task` | OLED驱动底层刷新；正式业务优先注册`OLED_Update`，不要重复刷新。 |
| `Drv_Servo_Task` | 舵机驱动后台入口；当前舵机角度命令可立即生效，按驱动使用方式决定是否注册。 |
| `Gimbal_Update` | 云台控制层入口；与`GimbalApp_Update`按调用链选择，避免同周期重复控制。 |
| `GimbalApp_Update` | 云台APP编排入口；正式业务优先使用该上层入口。 |
| `H2Task_Update` | H2业务状态机入口；当前滚球联调阶段不注册。 |
| `Heading_Update` | 航向控制入口；必须保证其所需传感器数据先更新。 |
| `LcdUi_Update` | LCD界面逻辑直接入口；通常由`LCD_Update`统一调用。 |
| `LineFollow_Update` | 巡线控制算法入口；正式业务优先注册`LineTrack_Update`。 |
| `Log_Update` | 日志周期输出入口；注册前确认当前日志源和输出串口不会影响实时控制。 |
| `OledUi_Update` | OLED界面逻辑直接入口；通常由`OLED_Update`统一调用。 |
| `TaskFSM_Update` | 通用任务状态机入口；与具体业务状态机按项目阶段择一注册。 |

本手册的文档检查会反向扫描各层公共头文件：新增零参数、`void`返回且名称以
`Update`、`Task`、`Run`、`Toggle`、`Ramp`、`Scan`或`Background`结尾的
公共入口后，如果未在本手册出现，`Test/host/check_test_docs.ps1`将检查失败。
