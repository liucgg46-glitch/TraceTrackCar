# STM32F407原工程测试任务完整手册

> 源码基准：`cb3930615de85206736befae299008bb15f11a24`，并包含蜂鸣器KEY1长响修复。本文以“复制任务表即可测试”为目标，每一项给出完整任务表、操作、输出和通过标准。

## 0. 使用前必须完成

1. 将 `Test/test_config.h` 中的 `PROJECT_TEST_TASKS_ENABLE`设为`1U`。
2. 在 `APP/app_task_config.h` 中包含 `test.h`。
3. 确认 `Test/test.c`参与 Keil Target；K210 专项测试还要加入 `Test/test_k210_comm.c`。
4. 每次只复制本文一个完整任务表，不从不同章节抽几行拼接。
5. 测试结束后恢复正式任务表，并将测试开关恢复为`0U`。

### 统一规则

- 除 GPIO 专项外，运行心跳统一使用 `AppDiagnostics_HeartbeatUpdate()`。
- `Test_GPIO_Toggle()`只用于 GPIO 专项，不再充当其他测试的运行指示。
- `AppTask_BSP_Background()`必须保留。
- 按键任务顺序：`Key_Update()`在消费事件的任务之前。
- 传感器任务顺序：`Sensor_Update()`在读取缓存的测试之前。
- 底盘任务顺序：`Encoder_Update()`在 `Chassis_Update()`之前。
- 同时只能有一个任务控制电机或显示页面。

## 1. BSP 普通 GPIO 翻转测试

**对应入口：**`Test_GPIO_Toggle`

### 可直接复制的完整任务表

```c
#define APP_SCHEDULER_TASK_LIST_DEFINE()                         \
Task_t task_list[] = {                                           \
    { AppTask_BSP_Background, 1U, 0U }, /* 后台维护 */                  \
    { Test_GPIO_Toggle, 10U, 0U }, /* 测试 BSP_GPIO_CH1 */            \
};                                                               \
const uint8_t TASK_NUM =                                         \
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

`Test_GPIO_Toggle()`每 500 ms 翻转一次 `PC13 / BSP_GPIO_CH1`。本项不要再注册
`AppDiagnostics_HeartbeatUpdate()`，因为两者控制同一个逻辑 GPIO，同时翻转会导致现象混乱。

**通过标准：**对应 LED 或测试引脚稳定以约 1 Hz 的亮灭周期变化。

## 3. 蜂鸣器按键测试

**对应入口：**`Test_Buzzer_Update`

### 可直接复制的完整任务表

```c
#define APP_SCHEDULER_TASK_LIST_DEFINE()                         \
Task_t task_list[] = {                                           \
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */         \
    { AppTask_BSP_Background, 1U, 0U }, /* UART、总线和异步驱动后台 */        \
    { Key_Update, 10U, 0U }, /* 按键扫描与消抖 */                          \
    { Test_Buzzer_Update, 10U, 0U }, /* 蜂鸣器控制 */                    \
};                                                               \
const uint8_t TASK_NUM =                                         \
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

当前蜂鸣器接在`PG7`，按低电平有效配置。按键行为如下：

| 按键 | 行为 |
| --- | --- |
| KEY1（PE4） | 按下一次后持续鸣响；稳定按住也能触发，避免按下边沿被清除后无响应 |
| KEY2（PE3） | 进入间歇鸣响模式，每500 ms翻转一次 |
| KEY3（PE2） | 立即停止；同一轮多个按键触发时停止优先 |
| KEY4、KEY5 | 不使用 |

上电后任务会先等待KEY1～KEY3全部稳定松开约100 ms，再接受控制。测试结束前按KEY3确认关闭。该函数不发送串口日志。

通过USART1 调试串口发送：

| 命令 | 行为 |
| --- | --- |
| `1`、`l`、`L` | 启动循迹 |
| `0` 或 `x` | 停止并停车 |
| `w` | 记录当前 8 路值为白底 |
| `b` | 记录当前 8 路值为黑线 |
| `t` | 生成 8 路阈值 |
| `d` | 恢复默认阈值 |
| `p` | 立即打印 RAW/FILT/TH/mask/error/type/output |
| `k` | 扫描 I2C |

数字量模式不需要执行白底/黑线模拟量阈值标定，直接使用`p`确认0/1状态后
发送`1`启动即可。`w`、`b`和`t`仅保留给模拟量兼容模式。

当前默认灰度来源为Yahboom 8路串口灰度模块数字量模式，使用USART3：
模块`RX`接`PD8/USART3_TX`，模块`TX`接`PD9/USART3_RX`，5V供电并与主控
共地，串口参数115200 8N1。上电约3秒且连续收到有效数字帧后判断在线。

白底应表现为`RAW=1/FILT=4095`、`mask=0x00`、`type=LOST`；黑线通道
应表现为`RAW=0/FILT=0`并进入`mask`。全部探头压黑线时可出现
`mask=0xFF`、`type=FULL`。

## 37. PF8摆杆舵机开环安全标定

**对应入口：**`Test_ServoBeamCalibration_Update`

当前`APP/app_task_config.h`已经通过`PROJECT_TEST_TASKS_ENABLE`条件编译保留
本测试和正式H2任务表。标定交付版本使用：

```c
#define APP_SCHEDULER_TASK_LIST_DEFINE()                                            \
Task_t task_list[] = {                                                              \
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */                    \
    { AppTask_BSP_Background, 1U, 0U }, /* UART和舵机Driver后台 */                 \
    { Key_Update, 10U, 0U }, /* 按键扫描和消抖 */                                  \
    { Test_ServoBeamCalibration_Update, 10U, 0U }, /* PF8舵机安全标定 */          \
};                                                                                  \
const uint8_t TASK_NUM =                                                             \
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

PF8连接WHEELTEC S20F信号线，舵机使用独立BEC并与STM32共地。上电立即输出
1500us并保持锁定；KEY1回中并解锁，KEY2增加5us，KEY3减少5us，KEY4立即
回中并锁定，KEY5打印状态和帮助。Driver将任何请求硬限制在1450～1550us，
不自动扫描，不注册底盘、循迹、传感器或显示任务。

完成标定后，将`Test/test_config.h`中的`PROJECT_TEST_TASKS_ENABLE`恢复为
`0U`，即可自动回到正式H2任务表。
