## 一、车辆运动控制参数：Algorithm/control_config.h

底盘PWM前馈与车轮速度PI、灰度循迹PD和动作库转向P的默认参数集中在`Algorithm/control_config.h`。`APP/chassis.h`、`APP/motion_action.h`和`Algorithm/line_track.h`只保留接口和数据结构，不再放调参宏。

上层仍使用`cps`形式的目标值；底盘先计算固定比例PWM前馈，再用各驱动轮独立的编码器速度PI修正。实际控制链如下：

`灰度位置误差 → LineTrack PD生成linear/turn（cps）→ left=linear-turn、right=linear+turn → PWM前馈＋各驱动轮PI修正 → 电机PWM（千分比）`

`Chassis_Update()`、`Drv_Encoder_Update()`和`LineTrack_Compute()`通常每10 ms调用一次。速度PI、灰度PD和命令步进都按“每次调用”计算，改变任务周期后必须重新验证对应的`KI`、`KD`和步进参数。

### 1.0 灰度循迹安装方向

```c
#define CONTROL_LINE_DIRECTION_REVERSE 1U
```

- `0U`：保持当前Driver输出的左右方向；规范化后线路在左时误差为负、线路在右时误差为正。
- `1U`：传感器整体旋转180度、循迹左右相反时使用；算法会同时反转位置误差、`black_mask`位序和左右分支类型。
- 该开关不重排逐路阈值。`LINE_DETECT_DEFAULT_THRESHOLD_0`～`_7`始终与Driver输出的物理通道一一对应，旋转传感器后不要手工倒序阈值；若安装高度或角度变化，应重新执行黑白标定。
- `DRV_GRAY_MCU_INDEX_REVERSE`和`DRV_GRAY_4051_INDEX_REVERSE`用于处理底层通道接线/编号。只改变传感器安装朝向时优先修改`CONTROL_LINE_DIRECTION_REVERSE`，不要同时修改两层反向开关。

### 1.1 底盘PWM前馈与车轮速度PI闭环

默认使用前馈＋PI闭环：前馈负责给出接近目标速度所需的基础PWM，PI只修正负载、电机差异和电压变化造成的速度误差。FL、FR（4WD时还包括RL、RR）各自保存独立的PI状态，但共用同一组增益。上层命令先经过目标斜坡再进入前馈和PI；停车、释放控制权、急停以及目标方向反转时会复位相应积分。

最终输出关系为：

`电机PWM = 目标cps×PWM上限/前馈满速cps + KP×速度误差 + KI×误差累计 + KD×误差变化`

最终PWM统一限制在`±CONTROL_CHASSIS_PWM_MAX_PERMILLE`。PID实现包含积分限幅和输出饱和方向上的暂停积分，避免编码器断线或负载过大时继续积累无效积分。

#### 当前通过测试的基线（2026-07-20）

默认2WD、10 ms编码器/底盘周期下，1600 cps测试时FL/FR滤波反馈均稳定在目标附近，后续阶跃加速和Basic循迹回归正常；起步曾观察到约1689 cps的短暂峰值，约5.6%超调，随后自行稳定且没有持续振荡。目标斜坡、无反馈保护、方向错误保护、命令租约超时保护、故障锁存及停车后清除也已完成实车测试。当前参数可作为这套电机、供电和负载的基线，更换硬件或任务周期后仍需重新验证。

| 参数 | 当前值 | 作用 |
| --- | ---: | --- |
| `CONTROL_CHASSIS_SPEED_LOOP_ENABLE` | `1U` | `1U`启用前馈＋PI；`0U`退回固定前馈开环，便于标定和排障 |
| `CONTROL_CHASSIS_PWM_MAX_PERMILLE` | `800` | 最终PWM硬限幅约为±80%占空比 |
| `CONTROL_CHASSIS_TARGET_MAX_CPS` | `5000` | 上层左右轮目标安全限幅，不代表电机已实测能达到该速度 |
| `CONTROL_CHASSIS_FEEDFORWARD_FULL_SPEED_CPS` | `5000` | 前馈标定：该目标对应`CONTROL_CHASSIS_PWM_MAX_PERMILLE` |
| `CONTROL_CHASSIS_SPEED_KP` | `0.08f` | 当前速度误差100 cps时产生8‰比例修正 |
| `CONTROL_CHASSIS_SPEED_KI` | `0.002f` | 每10 ms按误差累计积分修正 |
| `CONTROL_CHASSIS_SPEED_KD` | `0.0f` | 当前不使用微分，避免放大编码器量化噪声 |

| `CONTROL_CHASSIS_ENCODER_FAULT_ENABLE` | `1U` | 仅在速度闭环开启时启用编码器安全保护；`0U`用于专项排障，不建议正常运行时关闭 |
| `CONTROL_CHASSIS_FAULT_MIN_TARGET_CPS` | `800` | 实际控制目标绝对值达到该值后才允许进入故障监控 |
| `CONTROL_CHASSIS_FAULT_MIN_OUTPUT_PERMILLE` | `160` | 最终PWM绝对值达到该值后才允许进入故障监控 |
| `CONTROL_CHASSIS_FAULT_MAX_FEEDBACK_CPS` | `200` | 反馈绝对值不超过该值时视为无有效反馈候选 |
| `CONTROL_CHASSIS_NO_FEEDBACK_TIMEOUT_MS` | `500U` | 无有效反馈连续达到该时间后锁存`CHASSIS_FAULT_ENCODER_NO_FEEDBACK` |
| `CONTROL_CHASSIS_DIRECTION_MIN_FEEDBACK_CPS` | `300` | 反馈绝对值达到该值且方向持续与目标/输出相反时进入方向故障计时 |
| `CONTROL_CHASSIS_DIRECTION_TIMEOUT_MS` | `500U` | 方向错误连续达到该时间后锁存`CHASSIS_FAULT_ENCODER_DIRECTION` |
| `CONTROL_CHASSIS_FAULT_CLEAR_MAX_CPS` | `100` | 所有启用车轮原始速度绝对值不超过该值时才允许清除故障 |

| `CONTROL_CHASSIS_COMMAND_TIMEOUT_MS` | `200U` | 从最近一次有效`Chassis_SetSpeed()`开始计算的命令租约时限 |

`CONTROL_CHASSIS_TARGET_MAX_CPS`只负责命令限幅，`CONTROL_CHASSIS_FEEDFORWARD_FULL_SPEED_CPS`只负责前馈标定，不能再把两者当作同一个参数。稳态日志中`pi`长期为较大正数说明前馈偏小，应减小`CONTROL_CHASSIS_FEEDFORWARD_FULL_SPEED_CPS`；`pi`长期为较大负数说明前馈偏大，应增大该值。

开环标定时可暂设`CONTROL_CHASSIS_SPEED_LOOP_ENABLE=0U`，记录目标`T`和稳定实际速度`S`，按下式估算新前馈值：

`新的CONTROL_CHASSIS_FEEDFORWARD_FULL_SPEED_CPS = 当前值 × S ÷ T`

#### 编码器速度滤波

`Driver/drv_encoder.h`默认启用一阶低通：

```c
#define DRV_ENCODER_SPEED_FILTER_ENABLE       1U
#define DRV_ENCODER_SPEED_FILTER_ALPHA_NUM    1L
#define DRV_ENCODER_SPEED_FILTER_ALPHA_DEN    4L
```

滤波关系为`filtered += (raw-filtered)×NUM/DEN`。`1/2`响应更快但更容易抖，`1/6`更平滑但延迟更大；默认`1/4`已经通过当前速度环和循迹测试。`Drv_Encoder_GetWheelRawSpeedCps()`用于观察原始速度，`Drv_Encoder_GetWheelSpeedCps()`返回供控制层使用的滤波速度。

#### 五按键底盘速度测试参数

| 宏 | 当前值 | 按键行为 |
| --- | ---: | --- |
| `TEST_CHASSIS_INITIAL_LINEAR_CPS` | `1600` | KEY1：从该速度前进，并重置加速档位 |
| `TEST_CHASSIS_LINEAR_STEP_CPS` | `200` | KEY2：每个消抖后的按下沿增加一次 |
| `TEST_CHASSIS_LINEAR_MAX_CPS` | `4800` | KEY2：达到该值后不再增加 |

KEY5先调用`Chassis_EmergencyStop()`，会清零目标、前馈、PI状态和电机输出并释放底盘控制权，随后调用`Chassis_ClearFault()`。若车轮原始速度仍高于100 cps，会提示等待车轮停止后再按一次KEY5。上电后或KEY5停止后，必须重新按KEY1才能使用KEY2加速。命令有效期间，普通`Test_ChassisCmd_Update()`会每10 ms刷新一次速度命令租约；专项`Test_ChassisWatchdog_Update()`则故意只发送一次命令。正式模块调用`Chassis_EmergencyStop()`不会自动清除已锁存故障，修复原因并确认停车后必须显式调用`Chassis_ClearFault()`。

#### 故障码和故障轮掩码

| `fault` | 含义 |
| ---: | --- |
| `0` | `CHASSIS_FAULT_NONE`，无故障 |
| `1` | `CHASSIS_FAULT_ENCODER_NO_FEEDBACK`，满足目标和输出门槛后，编码器反馈连续500 ms过低 |
| `2` | `CHASSIS_FAULT_ENCODER_DIRECTION`，目标、输出同向但编码器反馈连续500 ms反向 |
| `3` | `CHASSIS_FAULT_COMMAND_TIMEOUT`，速度模式命令连续200 ms没有刷新；该故障不对应单个车轮，因此`mask=00` |

`mask`按位标记故障车轮：`0x01=FL`、`0x02=FR`、`0x04=RL`、`0x08=RR`。故障触发后底盘立即停止、释放控制权并保持锁存；锁存期间`Chassis_AcquireControl()`和`Chassis_SetSpeed()`都会拒绝新命令。无反馈保护能覆盖编码器断线、接头松动、堵转等表现，但软件不能仅凭该故障区分电气断线和机械堵转，仍需检查实物。

日志字段`age`是当前速度命令年龄，单位ms。正常10 ms任务应长期在约0～10 ms内刷新；若达到`CONTROL_CHASSIS_COMMAND_TIMEOUT_MS`，底盘锁存`fault=3 mask=00`、立即停车并释放控制权。调大超时时间可容忍更长的任务抖动，但失控停车更慢；调小会更快停车，但必须给正常调度延迟留出余量。该保护依赖`Chassis_Update()`继续运行，不能覆盖整个调度器停止执行的情况；需要覆盖整机卡死时应另行配置硬件独立看门狗。

#### 更换电机、负载或任务周期后的调参顺序

1. 悬空车轮确认命令目标`cmd`、斜坡后目标`tgt`、原始反馈和滤波反馈方向一致；任一驱动轮反馈始终为0时等待保护停车，再检查编码器接头、A/B相、映射和引脚，不得通过提高PI或关闭保护掩盖硬件问题。
2. 暂时关闭速度环，标定`CONTROL_CHASSIS_FEEDFORWARD_FULL_SPEED_CPS`。
3. 启用速度环，将`KI=0`、`KD=0`，从`KP=0.04f`开始，每次约增加`0.02f`，直到响应足够快且没有持续振荡。
4. 保持`KD=0`，将`KI`从`0.0005f`开始，每次增加`0.0005f`，用于消除稳态误差；出现慢速摆动、过冲或停车拖尾时降低`KI`。
5. `KD`默认保持0。只有反馈足够平滑且确有明显过冲时才小量尝试。
6. 内环稳定后再恢复循迹任务并调外环PD；一次只改一类参数。

#### 常见问题

| 现象 | 判断与处理 |
| --- | --- |
| 某轮`raw`和`fb`始终为0 | 达到目标、输出和500 ms门槛后应锁存`fault=1`并停车；检查编码器断线、接头松动、堵转、映射或引脚问题 |
| 某轮反馈方向与`cmd/tgt/out`相反 | 反馈绝对值达到300 cps并持续500 ms后应锁存`fault=2`；检查A/B相、方向宏和轮位映射 |
| 故障后KEY1～KEY4都被拒绝 | 属于故障锁存的正常行为；修复原因、等待所有启用轮`|raw|<=100 cps`，再按KEY5或调用`Chassis_ClearFault()` |
| 反馈围绕目标周期性大幅摆动，`out`同步大幅变化 | `KP`或`KI`过大；一次只降低一个参数 |
| 反馈稳定但持续低于目标，输出未饱和 | 先校准前馈，再小步增加`KI`或`KP` |
| 输出长期达到±800但仍达不到目标 | 已达到软件输出上限；检查供电、电机能力、机械负载和目标是否可达 |
| 只有起步出现小幅峰值，随后迅速稳定 | 小幅瞬态超调可接受；若冲击影响机械或循迹，先减小`CONTROL_CHASSIS_TARGET_SLEW_STEP_CPS`，再评估是否降低`KP/KI` |
| 停车后输出或积分没有归零 | 检查是否通过`Chassis_Stop()`、`Chassis_ReleaseControl()`或`Chassis_EmergencyStop()`进入统一停车路径 |

### 1.2 灰度位置 PD——让车沿着线走

#### 大白话解释

灰度PD决定“车该往哪走、走多快”，底盘再用前馈＋PI让各驱动轮跟踪目标速度。它做的事：

1. 8 路灰度传感器看到深色线路的位置，算出一个误差值（-3500 到 +3500，负数=线在左边，正数=线在右边）；当前赛题红线相对白底满足该判定关系
2. 用 PD 公式算出”该拐多少”：**转向量 = -(KP × 误差 + KD × 误差变化量)**
3. 根据误差大小自动减速（偏离越多越慢）
4. 把计算结果（linear + turn）发给底盘差速模型，由车轮速度内环生成电机PWM

完整数据流：

```
8路灰度传感器（模拟ADC值，0~4095）
  → LineDetect（与阈值比较→黑白二值→加权平均→误差 -3500~+3500）
    → LineTrack PD（误差→转向量 + 自适应速度）
      → Chassis_SetSpeed(linear, turn) → PWM前馈＋车轮速度PI → PWM
```

> 调试时先确认左右电机方向、编码器方向和车轮速度内环稳定，再调灰度PD。

当前实测基线：默认MCU-I2C灰度模块、现有逐路阈值和循迹参数已经在赛题红色实线上完成落地测试，小车能够沿红线行驶。算法中的`BLACK`字段名表示相对白底更深的线路响应，不要求实物线路必须是黑色。

#### 第二步：确认灰度传感器能正常看到线

**这一步比调 PD 更重要。传感器看不到线，PD 再好也没用。**

0. **悬空所有车轮（架起来）**，防止车突然冲出去。
1. 烧录循迹任务表，上电，用一个黑胶带/黑线放在传感器下方。
2. 查看路线LCD/OLED调试页的`RAW`和`FIL`。`Test_RouteLog`只负责激活页面，`LCD_Update`/`OLED_Update`负责对应屏幕刷新，不再发送串口日志：

| 你把黑线放在哪 | raw_error 应该是 | 说明 |
| --- | ---: | --- |
| 正中间（传感器 3~4 之间） | 接近 0（±200 以内） | ✅ 正常 |
| 最左边（传感器 0） | 接近 -3500 | ✅ 正常 |
| 最右边（传感器 7） | 接近 +3500 | ✅ 正常 |
| 左右移动黑线 | 数值平滑跟随变化 | ✅ 正常 |
| 黑线在任意位置都显示 LOST 或 error 不变 | — | ❌ 阈值不对，需要校准 |

3. 如果 error 完全不跟踪黑线位置，**先校准阈值**。方法：
   - 把传感器放白底上（不要有黑线），调用 `LineDetect_CaptureWhite()`
   - 把黑线放到传感器正下方，调用 `LineDetect_CaptureBlack()`
   - 调用 `LineDetect_MakeThresholdFromWhiteBlack()`
   - 或者在串口用 `p` 命令查看当前 8 路 ADC 值，手动改 `LINE_DETECT_DEFAULT_THRESHOLD_0~7`

#### 第三步：PD 调参（核心）

PD 公式：**转向 = -(KP × 误差 + KD × (误差 - 上次误差))**

其中误差范围 -3500~+3500，负号的意思是”线在左边就往左拐”。

| 参数 | 通俗解释 | 怎么调 |
| --- | --- | --- |
| **`CONTROL_LINE_KP`** | **“偏了多少就拐多少”**，误差乘KP后形成主要转向量。 | 弯道拉不回来时小步增加；出现蛇形或边缘猛转时降低。 |
| **`CONTROL_LINE_KD`** | **“误差变化有多快”**，使用相邻10 ms误差之差；灰度跳格也会被放大。 | KP稳定后从较小值开始；出现高频反向转向时降低或设0。 |
| **`CONTROL_LINE_ERROR_DEADBAND`** | 误差绝对值小于该范围时按0处理。 | 中线附近小幅抖动时增大；中线修正迟钝时减小。 |
| **`CONTROL_LINE_BASE_SPEED_CPS`** | 中线附近的基础前进命令。 | 调试时先低速，PD稳定后再逐步提高。 |
| **`CONTROL_LINE_MIN_TRACK_SPEED_CPS`** | 普通大偏差时允许降到的最低前进命令。 | 弯道冲出时降低；电机推不动车时提高。 |
| **`CONTROL_LINE_TURN_MAX_CPS`** | 普通循迹转向硬限幅；继续增大KP/KD也不能突破它。 | 转不过来时小步提高，转向过猛或跨过中线时降低。 |

**PD 调参顺序（放地上跑）：**

1. **降速起步**：`BASE_SPEED_CPS` 改成 1500，KD 改成 0
2. **只调 KP**：从 0.3 开始每次加 0.1，观察车在直线上有没有来回摆。出现蛇形（车位来回晃）就减 0.05。记下刚好不摆的 KP 值。
3. **加 KD**：KP 确定后，KD 从 0.05 加起。KD 加够时车在直线会非常稳，弯道入弯也更平滑。但如果 KD 加了反而更抖，说明传感器噪声大——退回 KD=0。
4. **提速**：逐步提高 `BASE_SPEED_CPS` 到 2000、2500、3000，每次提速后确认直线不摆、弯道能跟上。

#### 第四步：速度自适应参数

外环会根据误差绝对值自动减速：

```
误差 ≤ SPEED_FULL_ERROR  → BASE_SPEED_CPS
两阈值之间                 → 线性降速
误差 ≥ SPEED_MIN_ERROR   → MIN_TRACK_SPEED_CPS
```

| 参数 | 作用 | 怎么调 |
| --- | --- | --- |
| `CONTROL_LINE_SPEED_FULL_ERROR` | 误差在此范围内保持基础速度 | 中线附近不应减速时增大；希望更早减速时减小 |
| `CONTROL_LINE_SPEED_MIN_ERROR` | 误差达到此值后使用最低循迹速度 | 急弯来不及减速时减小 |
| `CONTROL_LINE_MIN_TRACK_SPEED_CPS` | 大偏差最低前进速度 | 弯道太慢时增大；弯道冲出时减小 |

#### 第五步：最外侧误差处理

独立`EDGE`边缘救线模式已经取消。最外侧传感器压线时仍使用同一套基础PD，并受`CONTROL_LINE_TURN_MAX_CPS`限幅；不会再强制最低转向量。

边缘转向过猛时优先降低`CONTROL_LINE_KP`或`CONTROL_LINE_TURN_MAX_CPS`；拉不回来时反向调整，并同时检查基础速度。

#### 第六步：丢线搜索参数

当所有传感器都看不到黑线时，先连续确认2帧，过滤单帧干扰；随后沿最后看到线路的方向开始原地找线，并在后续阶段交替方向、逐步增加扫描时间和转向量。重新看到线路必须连续确认3帧才恢复PD，首次丢线累计达到10秒仍未恢复则安全停车。

| 参数 | 作用 |
| --- | --- |
| `CONTROL_LINE_LOST_CONFIRM_SAMPLES` | `2U`，连续丢线确认帧数；10 ms周期下约20 ms进入搜索 |
| `CONTROL_LINE_REACQUIRE_CONFIRM_SAMPLES` | `3U`，搜索时连续重新看到线路的确认帧数 |
| `CONTROL_LINE_SEARCH_TURN_CPS` | `1000`，第0阶段沿最后线路方向原地搜索的转向量 |
| `CONTROL_LINE_SEARCH_TURN_STEP_CPS` | `200`，每增加一个扫描阶段的转向量增量 |
| `CONTROL_LINE_SEARCH_TURN_MAX_CPS` | `1800`，扩大搜索的转向量上限 |
| `CONTROL_LINE_SEARCH_INITIAL_PHASE_MS` | `300U`，第0阶段扫描时间 |
| `CONTROL_LINE_SEARCH_PHASE_STEP_MS` | `200U`，每阶段增加的扫描时间 |
| `CONTROL_LINE_SEARCH_PHASE_MAX_MS` | `900U`，单阶段扫描时间上限 |
| `CONTROL_LINE_SEARCH_TIMEOUT_MS` | `10000U`，从首次丢线开始计算的安全停车超时 |

默认阶段依次为：`P0：300 ms/1000 cps`、`P1：500 ms/1200 cps`、`P2：700 ms/1400 cps`、`P3：900 ms/1600 cps`，从`P4`开始保持`900 ms/1800 cps`并继续交替方向。搜索参数一般不调；若正常循迹频繁丢线，应先检查阈值、安装高度和线路质量，再降低基础速度。

#### 快速参考：常见现象和怎么改

| 现象 | 优先改什么 | 怎么改 |
| --- | --- | --- |
| 直线左右来回摆（蛇形） | KP 太大 / 没 KD | 减小 KP 0.05~0.1，或加 KD 0.05~0.1 |
| 直线很稳但弯道拐不过来 | KP 太小 | 加大 KP 0.1~0.2 |
| 入弯不减速直接冲出去 | DECEL_STEP 太小 / BASE_SPEED 太大 | 先降 BASE_SPEED，再加大 DECEL_STEP |
| 出弯后加速太慢 | ACCEL_STEP 太小 | 加大到 150~200 |
| 传感器明明看到线但 error 不对 | 阈值问题 | 重新校准白/黑采样 → MakeThreshold |
| 中线附近小幅高频抖动 | DEADBAND 太小 | 加大到 120~200 |
| 转向太猛、动作生硬 | `CONTROL_CHASSIS_TARGET_SLEW_STEP_CPS`过大 | 减小该值可让左右目标变化更平滑，但响应和故障监控进入门槛也会相应变慢，修改后需重新实测 |
| 弯道内侧轮居然反转了 | TURN_MAX 太大 | 代码限制 turn ≤ linear，但 linear 很小时 turn_max 也可能超过它。降低 TURN_MAX 或提高最低 linear 速度 |
| 频繁进入丢线搜索 | 传感器看不到线 | 先校准阈值，再降 BASE_SPEED |

> **PD参数关系**：`SPEED_FULL_ERROR < SPEED_MIN_ERROR`必须成立，否则速度计算会出错。搜索参数也有类似约束，见`Algorithm/control_config.h`注释。

### 1.3 常见现象与优先调节项

> ⚠️ **调试铁律：先内环后外环。** 车轮速度 PID（内环）没调好之前，循迹 PD（外环）怎么调都是白费。如果某个轮子一直跟不上目标，问题出在速度环，**不要用外环的 KP/KD 去补偿**。

| 现象 | 优先检查/调节 | 说明 |
| --- | --- | --- |
| **速度环问题**（现象发生在单个轮子上） | | |
| 左右轮在相同目标下实际速度差异明显 | 先比较`raw`、`fb`、`ff`、`pi`和`out` | 内环会独立补偿电机差异；某轮反馈为0或符号错误时必须先修复编码器 |
| 轮速稳定但总低于目标（如目标2000，稳定在1500） | 先检查输出是否长期达到`800‰`，再按当前`KP=0.08f、KI=0.002f`小步调整 | 输出已饱和时继续加PI不会提高电机物理能力 |
| 轮子空载正常，放地上就明显变慢 | 检查供电压降、机械负载和PWM是否饱和；未饱和时先校准前馈 | 前馈正确后再小幅调整KP或KI |
| 起步那一下轮子小幅超调，然后迅速稳定 | 先看是否持续振荡 | 当前1600 cps起步约5.6%瞬态超调已通过测试；若机械冲击不可接受先减小`CONTROL_CHASSIS_TARGET_SLEW_STEP_CPS`，再评估KP/KI |
| 两侧轮子行为明显不同 | **对调电机/编码器排查硬件**，确认接头、齿轮间隙和轴承顺滑度 | 不要用不同PI参数掩盖断线、松动或机械故障 |
| **循迹外环问题**（现象发生在整车轨迹上） | | |
| 中线附近连续小幅摆动 | 适当增大 `CONTROL_LINE_ERROR_DEADBAND`，再检查 `CONTROL_LINE_KP`、`CONTROL_LINE_KD` | 先排除阈值噪声和左右传感器顺序错误 |
| 偏离后拐大弯并冲出线 | 降低`CONTROL_LINE_BASE_SPEED_CPS`或`CONTROL_LINE_MIN_TRACK_SPEED_CPS`，再调`CONTROL_LINE_KP`和转向上限 | 底盘已有统一目标斜坡；仍冲出线时优先调整循迹外环，不要用过小斜坡掩盖方向或传感器问题 |
| 大误差时速度很低且突然急拐 | 提高`CONTROL_LINE_MIN_TRACK_SPEED_CPS`或降低`CONTROL_LINE_KP`、`CONTROL_LINE_TURN_MAX_CPS` | 当前最外侧也使用基础PD，没有独立边缘参数 |
| 已经到最外侧但拉不回来 | 先检查误差方向，再提高`CONTROL_LINE_KP`或`CONTROL_LINE_TURN_MAX_CPS`，必要时降低基础速度 | 不再存在强制最低救线转向 |
| 丢线后初始转向太弱或太强 | 调节`CONTROL_LINE_SEARCH_TURN_CPS` | 后续阶段还会受`TURN_STEP_CPS`和`TURN_MAX_CPS`影响 |
| 扫描换向太快或太慢 | 调节`CONTROL_LINE_SEARCH_INITIAL_PHASE_MS`、`PHASE_STEP_MS`和`PHASE_MAX_MS` | 第0阶段优先沿最后线路方向，后续阶段交替方向 |
| 偶尔一帧丢线仍影响车辆 | 先检查阈值，再按需增大`CONTROL_LINE_LOST_CONFIRM_SAMPLES` | 增大后抗干扰更强，但真正丢线时会多保持原命令若干帧 |
| 找到线后又立刻丢失 | 降低搜索强度、检查阈值，必要时增大`CONTROL_LINE_REACQUIRE_CONFIRM_SAMPLES` | 增大后恢复更稳，但重新起步稍慢 |

## 二、动作库参数（同样位于 Algorithm/control_config.h）

### 2.1 大白话解释

动作库做两件事：**直行指定距离** 和 **原地转指定角度**。它不直接控制 PWM，而是调用你刚调好的 `Chassis_SetSpeed()`，让底盘速度 PID（内环）来执行。所以 **内环必须先调好，再测动作库，否则距离和角度一定不准**。

动作的执行流程：

```
Motion_GoDistance(500mm, 1500cps)
  → Chassis_SetSpeed(±1500, 0)   // 直行，速度限幅在 [150, 4000]
  → 每 10ms：里程累加
  → 走了 ≥ (500 - 8)mm → 完成，停车

Motion_TurnAngle(90°)
  → 每 10ms：航向误差 × 25.0 = 转向速度，正常阶段限幅在 [1000, 3000]
  → Chassis_SetSpeed(0, 转向速度) // 原地差速转弯
  → 越过目标后：按误差反方向以 500cps 低速回正
  → 误差 ≤ 3° 持续 10 次采样（约100ms）→ 完成，停车
```

### 2.2 各参数详解

| 参数 | 当前值 | 建议值 | 通俗解释 |
| --- | ---: | ---: | --- |
| `CONTROL_MOTION_DISTANCE_TOLERANCE_MM` | `8` | **保持 `8`** | **”走到差多少算到”**。目标 500mm，实际走到 492mm 就判定完成。设太小（比如 1~2mm）会因为惯性永远到不了，设太大（比如 50mm）精度太差。8mm 大概是一个轮胎编码器 2~3 个计数的距离。 |
| `CONTROL_MOTION_ANGLE_TOLERANCE_DEG` | `3.0f` | **保持 `3.0f`** | **”转到差多少度算到”**。角度误差 ≤ 3° 时开始”稳定确认”。设太小（< 1°）容易来回修正卡住，设太大（> 5°）转角不准。3° 对小车来说肉眼几乎看不出来。 |
| `CONTROL_MOTION_DEFAULT_TIMEOUT_MS` | `8000U` | **保持 `8000`** | **”最多等多久”**。一个动作超过 8 秒还没完成就报错停车。500mm 以 1000cps 跑大概 1~2 秒，8 秒绰绰有余。如果车重、地滑或者目标距离很长，可以加大。 |
| `CONTROL_MOTION_MIN_ABS_SPEED_CPS` | `150` | **保持 `150`** | **”直行最慢速度”**。不管上层给多小的速度参数，实际发给底盘的不会低于 150cps。防止速度太低电机推不动。 |
| `CONTROL_MOTION_MAX_ABS_SPEED_CPS` | `4000` | **保持 `4000`** | **”动作速度总上限”**。直行动作传入的速度和统一转弯速度都会受此限制；低于底盘 `TARGET_MAX_CPS=5000`。 |
| `CONTROL_MOTION_TURN_SPEED_CPS` | `3000` | **统一使用** | **”定角转弯速度上限”**。测试代码和后续赛道动作入口调用`Motion_TurnAngle()`时不再各自传速度，全部共用此值。 |
| `CONTROL_MOTION_TURN_MIN_SPEED_CPS` | `1000` | **先保持 `1000`** | **”转弯最慢速度”**。即使角度误差很小（比如只剩 10°），转向速度也不会低于 1000cps。**这个参数最关键**——太大过冲严重、太小转不动。测试时如果每次转弯都转过头很多，优先减小这个值。 |
| `CONTROL_MOTION_TURN_CORRECTION_SPEED_CPS` | `500` | **先保持 `500`** | **”转过头以后往回修的速度”**。首次越过目标后锁定低速回正模式，方向始终跟随角度误差，直到重新进入±3°。太低可能克服不了静摩擦，太高可能再次跨过目标。 |
| `CONTROL_MOTION_TURN_KP_CPS_PER_DEG` | `25.0f` | **保持 `25.0f`观察** | **”角度差多少，转多快”**。误差90°时计算得到2250cps，未达到统一上限3000cps；误差低于40°时会受1000cps最小速度限制。 |
| `CONTROL_MOTION_TURN_SETTLE_SAMPLES` | `10U` | **保持 `10`** | **”稳定多久才算到”**。角度误差连续10次（每次10ms，共约100ms）都在±3°内才完成；若停车后因惯性越界，计数会清零并继续回正。 |

### 2.3 关键：理解转向速度的计算

以 `Motion_TurnAngle(90°)` 为例，实际输出速度是这样算的：

```
统一速度上限 = 3000
→ Motion_LimitSpeed: 限幅到 [150, 4000] → 还是 3000

每 10ms 实际转向速度：
  误差 90° → 90×25.0 = 2250cps
  误差 60° → 60×25.0 = 1500cps
  误差 30° → 30×25.0 = 750 → 低于 TURN_MIN → 取 1000cps
  误差 5°  → 5×25.0  = 125 → 低于 TURN_MIN → 取 1000cps
  误差 2°  → ≤ 容差 3° → 停车+稳定确认
  越过目标且误差反号 → 锁定500cps低速回正，方向随误差改变
```

**结论：正常转向阶段由KP、1000cps最小速度和3000cps统一上限共同决定；首次越过目标后不再使用1000cps最小速度，而是锁定500cps低速回正。** 这保证不同路线入口使用完全相同的定角控制，也避免转过头后高速反向修正。

### 2.4 推荐测试步骤

**第 1 步：直行距离测试**
- `Motion_GoDistance(300, 1000)` — 走 300mm，1000cps
- 实际测量走了多远，对比 `CONTROL_MOTION_DISTANCE_TOLERANCE_MM` 容差是否合理
- 如果总是差很多（比如目标 300 实际 250），先检查 `DRV_ENCODER_WHEEL_DIAMETER_MM` 和 `DRV_ENCODER_COUNTS_PER_REV`，**不是调动作库参数**

**第 2 步：转角测试（核心）**
- `Motion_TurnAngle(90)` — 按统一参数转 90°
- 在地上放一张纸，画好起始线和 90° 标记，看实际转了多少
- 如果明显转过头（比如转了 100°+），先观察是否会以500cps自动回到±3°；初次过冲太大可降低`TURN_MIN_SPEED_CPS`，回正仍越界则降低`TURN_CORRECTION_SPEED_CPS`
- 如果明显转不够（比如只转了 80°）：**增大 `TURN_MIN_SPEED_CPS`**，或者检查 IMU 航向是否正确
- 如果转完后来回晃很久才停下：**增大 `TURN_SETTLE_SAMPLES`** 到 5~8

**第 3 步：不同角度验证**
- 90° 调好后，试 45°、180°、360°
- 小角度（45°）主要验证 `TURN_MIN_SPEED_CPS` 是否合适
- 大角度（180°+）验证 `TURN_KP_CPS_PER_DEG` — 大弯应该明显比小弯快

### 2.5 快速参考：常见问题和怎么改

| 现象 | 优先改什么 | 怎么改 |
| --- | --- | --- |
| 走 500mm 实际只走了 400mm | 里程标定，不是动作库参数 | 调 `DRV_ENCODER_WHEEL_DIAMETER_MM` 和 `COUNTS_PER_REV` |
| 走 500mm 走了 550mm，但每次都很稳定 | 里程标定 | 同上 |
| 转 90° 首次超过100°但会返回 | 回正逻辑正常 | 观察最终是否稳定在±3°；需要减小初次过冲时再降低`TURN_MIN_SPEED_CPS` |
| 越过目标后无法往回移动 | `TURN_CORRECTION_SPEED_CPS` 太小 | 从500开始小幅增加，直到能克服静摩擦 |
| 低速回正仍反复跨过目标 | `TURN_CORRECTION_SPEED_CPS` 太大 | 每次降低50～100cps |
| 转 90° 每次只转了 ~70° | `TURN_MIN_SPEED_CPS` 太小 | 加到 1200，可能静摩擦太大推不动 |
| 转完后在原地小幅度来回摆动很久 | `TURN_SETTLE_SAMPLES` 太少 | 加到 5~8，让稳定确认更严格 |
| 动作执行到一半报 Error | 超时 | 检查 `DEFAULT_TIMEOUT_MS` 是否够；或者距离设太大、速度设太小 |
| 大角度转弯太慢 | `TURN_KP_CPS_PER_DEG` 太小 | 小幅增加，但最终不超过统一的`TURN_SPEED_CPS`上限 |
| 直行动作方向反了（让前进结果后退）| 编码器方向 | 检查 `DRV_ENCODER_WHEEL_DIR` 或电机接线 |

| `MEDICINE_ROUTE_END_MIN_TRAVEL_MM` | `250L` | 最后转弯或最后必经返程路口之后，允许终点门标判定的最小行程 |
| `MEDICINE_ROUTE_RETURN_SPEED_BOOST_CPS` | `500` | 只对返程正常单线循迹增加的速度 |
| `MEDICINE_ROUTE_RETURN_MAX_SPEED_CPS` | `3000` | 返程正常单线速度上限 |
| `MEDICINE_ROUTE_RIGHT_ANGLE_DEG` | `55` | Medicine左右路口定角动作；不改变180°掉头参数 |
| `MEDICINE_ROUTE_EVENT_IGNORE_MS` | `400U` | 启动或转弯后忽略脚下旧标志的时间 |

K210实际运行的Python程序、模型和启动入口已经同步到仓库`K210/`目录；部署时必须保持仓库与SD卡版本一致，不得继续使用旧示例中的IO8 TX结论。K210应使用稳定且电流充足、符合模块规格的电源，不建议直接由STM32开发板3.3V引脚供电。完整协议和验收说明见[《K210数字识别与STM32通信说明》](K210数字识别与STM32通信说明.md)。

## 十、E220-400T22D 硬件连接

| E220 引脚 | STM32F407 | 说明 |
| --- | --- | --- |
| RXD | PA9 / USART1_TX | STM32 向 E220 发送数据 |
| TXD | PA10 / USART1_RX | STM32 接收 E220 输出数据 |
| AUX | PE6 / BSP_GPIO_E220_AUX | 普通 GPIO 输入，无上下拉；低忙高闲；板级引出情况待确认 |
| M0 | GND | 透明传输模式要求低电平，不可悬空 |
| M1 | GND | 透明传输模式要求低电平，不可悬空 |
| GND | GND | STM32 与本地 E220 必须共地；两台远端 E220 之间不需要连接 GND |

USART1 保持 115200、8 数据位、无校验、1 停止位、无硬件流控。AUX 是模块输出，只需要普通 GPIO 输入，不需要定时器、ADC 或专用中断脚；本实现采用轮询。严禁把 PE6 配成输出低电平，也不要给 AUX 外接下拉，否则模块上电时可能被强制带入升级模式。

### （一）改变模块配置

改变E220-400T22D配置方法：打开E220  V1.3M0 M1接3.3，RX TX接USB转TTL，VCC GND正常接，USB转TTL接入电脑

配置时，M0、M1 临时接 3.3V 进入配置模式；RXD 接 USB-TTL 的 TX，TXD 接 USB-TTL 的 RX，VCC、GND 正常供电并与 USB-TTL 共地，USB-TTL 的 IO 电平必须为 3.3V。修改完成后先断电，再将 M0、M1 可靠接地，重新上电进入透明传输模式。收发两端的信道、地址、网络 ID、空中速率等无线参数必须匹配，串口参数保持 115200、8N1；具体配置项以所用固件和 E220 V1.3 配置软件实际显示为准。

## 十一、HX711 压力/称重模块硬件连接

| HX711 模块引脚 | STM32F407 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | 直接连接 STM32 时建议使用 3.3V 逻辑供电 |
| GND | GND | 必须共地 |
| DT / DOUT | PG3 / BSP_GPIO_HX711_DOUT | HX711 数据输出，驱动配置为上拉输入 |
| SCK / CLK / PD_SCK | PG4 / BSP_GPIO_HX711_PD_SCK | HX711 时钟和掉电控制，驱动保持默认低电平 |
| E+、E-、A+、A- | 称重传感器 | 按模块与传感器丝印连接，线色无统一标准 |

`Driver/drv_hx711.h` 中 `DRV_HX711_DEFAULT_SCALE_COUNTS_PER_G=695.93f`，由空载均值约 `-540045.3` 和 160.1 g 负载均值约 `-428626.8` 计算得到。每次上电必须保持称重台空载。HX711专项测试由驱动连续收集32个稳定样本自动去皮，10 SPS下约需3.2秒；正式送药状态机若克重尚未有效，会在`WAIT_TARGET`空载阶段等待500 ms后调用`Sensor_PressureTare()`。去皮完成后，`APP/sensor_manager.h`的`Sensor_GetPressureGram()`直接返回单位为g的缓存值，不需要串口命令。

## 十二、红绿状态灯硬件连接

| 功能 | STM32F407 | 业务别名 | 有效电平 | 实测状态 |
| --- | --- | --- | --- | --- |
| 红色状态灯 | PG5 | `BSP_GPIO_STATUS_RED` | 高电平点亮 | 通过 |
| 绿色状态灯 | PG6 | `BSP_GPIO_STATUS_GREEN` | 高电平点亮 | 通过 |

`Driver/drv_status_light.*`对上层提供`Drv_StatusLight_SetRed()`、`Drv_StatusLight_SetGreen()`和`Drv_StatusLight_Off()`。驱动只允许灭、红、绿三种状态，切换时先熄灭两灯再点亮目标灯，避免同时点亮。若以后更换为低电平有效模块，只修改`BSP_GPIO_STATUS_RED_ACTIVE_LEVEL`和`BSP_GPIO_STATUS_GREEN_ACTIVE_LEVEL`，GPIO上电初始电平会同步取反。
