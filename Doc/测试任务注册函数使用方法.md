# 测试任务注册函数使用方法

> 本文按当前项目源码校正。当前 `Doc` 目录未发现对应的 Word 原文件，因此本次只能同步 Markdown；若后续恢复 Word 文件，必须同时检查本文和 `说明文档.md`。

## 当前默认：五按键动作库测试

`APP/app_task_config.h` 当前注册：

```c
Task_t task_list[] = {
{ Test_GPIO_Toggle,        10U, 0U },
{ AppTask_BSP_Background,   1U, 0U },
{ Key_Update,              10U, 0U },
{ Sensor_Update,            1U, 0U },
{ Encoder_Update,          10U, 0U },
{ Test_MotionCmd_Update,   10U, 0U },
{ Motion_Update,           10U, 0U },
{ Chassis_Update,          10U, 0U },
{ Test_MotionCmd_Log,     200U, 0U },
};
```

`Key_Update()` 必须排在 `Test_MotionCmd_Update()` 之前，以生成消抖后的按下沿事件；`Sensor_Update()` 和 `Encoder_Update()` 必须先于动作更新。KEY1/KEY2 的定角动作会检查 IMU 是否完成初始化和静止标定，未准备好时拒绝启动。当前任务表不注册 `LCD_Update()`，因此动作测试不在 LCD 上显示，只通过 USART1 输出命令结果和周期日志。`Test_GPIO_Toggle` 是常驻运行指示灯，不能省略。

灰度按键校准和 Basic 路线循迹任务表仍保留在 `APP/app_task_config.h` 下方注释示例中，需要时再切换；`LineCalibration_Update()` 位于正式的 `APP/line_calibration.c`。

## 五按键专项测试（需要手动切换任务表）

要单独检查 KEY1～KEY5 时，将任务表切换为：

```c
Task_t task_list[] = {
{ Test_GPIO_Toggle,       10U, 0U },
{ AppTask_BSP_Background,  1U, 0U },
{ Key_Update,             10U, 0U },
{ Test_Key_Update,        10U, 0U },
};
```

`Key_Update()` 负责调用 `BSP_Key_UpdateAll()` 完成扫描和 20 ms 消抖，`Test_Key_Update()` 只读取并打印事件。两者都使用 10 ms 周期，并且 `Key_Update()` 必须排在前面。按键专项测试不需要注册 `Sensor_Update()`。USART1 使用 115200、8-N-1；普通直连模式下接 USB-TTL，E220 模式下日志从无线链路发出。

上电后先发送：

```text
KEY TEST READY: KEY1=PE4 KEY2=PE3 KEY3=PE2 KEY4=PE1 KEY5=PA15
```

每个按键稳定按下和松开各发送一行：

| 操作 | USART1 输出 |
| --- | --- |
| 按下/松开 KEY1（PE4） | `KEY1 PRESSED (PE4)` / `KEY1 RELEASED (PE4)` |
| 按下/松开 KEY2（PE3） | `KEY2 PRESSED (PE3)` / `KEY2 RELEASED (PE3)` |
| 按下/松开 KEY3（PE2） | `KEY3 PRESSED (PE2)` / `KEY3 RELEASED (PE2)` |
| 按下/松开 KEY4（PE1） | `KEY4 PRESSED (PE1)` / `KEY4 RELEASED (PE1)` |
| 按下/松开 KEY5（PA15） | `KEY5 PRESSED (PA15)` / `KEY5 RELEASED (PA15)` |

PA15 同时是 JTDI 复用脚。当前配置把它改为普通按键输入，因此完整 JTAG 不再可用；PA13/PA14 两线 SWD 下载和调试不受影响。仓库没有开发板原理图，KEY5 暂按与 KEY1～KEY4 相同的内部上拉、低电平按下方式配置，实际有效电平待实板确认。

## 二、底盘开环 PWM 测试

```c
{ Test_GPIO_Toggle,        10U,  0U }, \
{ AppTask_BSP_Background,   1U,  0U },  \
{ Key_Update,              10U,  0U },  \
{ Encoder_Update,          10U,  0U },  \
{ Test_ChassisCmd_Update,  10U,  0U },  \
{ Chassis_Update,          10U,  0U },  \
{ LCD_Update,              20U,  0U },  \
{ Test_ChassisCmd_Log,    200U,  0U },  \
```

KEY1（PE4）：线速度重置为 1600 cps 并前进

KEY2（PE3）：KEY1 启动后，线速度增加 200 cps 并继续前进，最大 4800 cps；达到上限后继续按仍保持 4800 cps

KEY3（PE2）：转向速度设为 +1600 cps，原地左转

KEY4（PE1）：转向速度设为 -1600 cps，原地右转

KEY5（PA15）：立即调用 `Chassis_Stop()` 停止并清零电机输出

每个按键只处理消抖后的按下沿，按住不会连续加速。上电后或 KEY5 停止后，KEY2 不会单独启动车轮，必须重新按 KEY1；KEY1 会把加速档位置为 1600 cps。串口每 200 ms 输出左右目标、编码器反馈和实际 PWM，按键动作也会立即输出一行确认日志。

### 串口日志字段

周期日志格式为：

```text
CHS mode=1 tgt L=1000 R=1000 | fb FL=930 FR=910 RL=0 RR=0 | out 56 72 0 0
```

| 字段 | 含义 |
| --- | --- |
| `mode=0/1` | `0` 为 `CHASSIS_MODE_STOP`，`1` 为 `CHASSIS_MODE_SPEED` |
| `tgt L/R` | 左侧、右侧车轮目标速度，单位 cps；由 `left=linear-turn`、`right=linear+turn` 得到 |
| `fb FL/FR/RL/RR` | 前左、前右、后左、后右编码器实际速度，单位 cps；当前 2WD 下 RL/RR 为 0 |
| `out FL/FR/RL/RR` | 由目标 `cps` 固定比例换算的电机 PWM 千分比；例如 `800` 约为 80% 占空比，负值表示反转 |

### LCD 开环 PWM 测试页面

`Test_ChassisCmd_Update()`首次运行时调用`LcdUi_ChassisTestBegin()`激活专用页面，`LCD_Update`负责非阻塞刷新。因此只有任务表同时注册这两个任务时才显示开环测试数据；只注册`LCD_Update`会显示普通仪表盘，灰度校准任务则切换到校准页面。

| LCD 字段 | 含义 |
| --- | --- |
| `MODE` | `STOP` 为停止，`SPEED` 为目标值开环输出状态 |
| `LIN / TURN` | 当前线速度和转向速度命令，单位 cps |
| `TGT L/R` | 左右侧目标速度，单位 cps |
| `FB1 L/R` | 前左 FL、前右 FR 实际编码器速度，单位 cps |
| `ERR1 L/R` | 前轮速度误差，计算为 `目标速度 - 实际速度`；正值表示实际偏慢，负值表示实际偏快 |
| `PWM1 L/R` | 前左、前右实际开环 PWM，单位为千分比 |
| `FB2 / ERR2 / PWM2` | 仅 4WD 显示后左 RL、后右 RR 数据；当前 2WD 改为显示按键提示 |

LCD 数据页约每 200 ms 更新一次。串口日志继续保留，便于保存完整四轮数据和调参记录。

## 五、灰度传感器与循迹状态调试（此任务表未注册 Motion_Update 和 Chassis_Update，不会实际驱动电机）

### （1）串口综合调试方式（原有）

```c
{ Test_GPIO_Toggle,       10U,  0U },  \
{ AppTask_BSP_Background,  1U,  0U }, \
{ Sensor_Update,           1U,   0U },   \
{ Encoder_Update,         10U,   0U },   \
{ LineTrack_Update,        10U, 0U },  \
{ Test_LineCmd_Update,     10U, 0U },  \
{ Test_LineCmd_Log,       200U, 0U },  \
```

·  w：将八路传感器全部放在白色区域，采集白色值。

·  b：将八路传感器全部放在黑色区域，采集黑色值。

·  t：根据白色和黑色值生成八路阈值。

·  d：将 8 路阈值统一设为 LINE_DETECT_DEFAULT_THRESHOLD（当前为 2000U）。

·  p：立即打印一次完整数据。

·  k：扫描 I2C1 设备。

·  1 / l / L：请求进入循迹状态（IMU 未就绪时可能被拒绝）。

·  0 或 x：停止循迹状态。

### （2）按键校准并在 LCD 显示阈值（需要校准时切换）

```c
Task_t task_list[] = {
{ Test_GPIO_Toggle,              10U, 0U }, /* 运行指示灯 */
{ AppTask_BSP_Background,         1U, 0U },
{ Key_Update,                    10U, 0U },
{ Sensor_Update,                  1U, 0U },
{ LineCalibration_Update,       10U, 0U },
{ LCD_Update,                    20U, 0U },
{ OLED_Update,                   20U, 0U },
};
```

使用步骤：

1. 上电后等待灰度传感器在线。因为任务表注册了`LineCalibration_Update()`，LCD/OLED启动页结束后进入`GRAY CALIBRATION`校准页面。
2. 把8路传感器全部放在白底上，等待滤波读数稳定后按KEY1（PE4）；LCD/OLED提示`WHITE CAPTURED`，串口输出`WHITE`和本次八路采样值。
3. 把8路传感器全部放在黑线上，等待滤波读数稳定后按KEY2（PE3）；LCD/OLED提示`BLACK CAPTURED`，串口输出`BLACK`和本次八路采样值。
4. 按KEY3（PE2）计算阈值。LCD显示逐路`TH0`～`TH7`，OLED以两路一行显示`T0`～`T7`，串口同时输出八行`LINE_DETECT_DEFAULT_THRESHOLD_0`～`_7`宏。
5. 若希望下次重新烧录后仍使用这些数值，把串口输出复制到 `Algorithm/line_detect.h`。STM32 运行时不能直接修改电脑上的源文件宏；本次计算值只在当前上电周期内生效。

必须先完成 KEY1 和 KEY2 采样才能按 KEY3；否则串口输出 `GRAY CAL WAIT: PRESS KEY1 AND KEY2 FIRST`。灰度传感器离线时不会记录无效样本。

## 八、测试定距前进、后退及定角转弯

```c
{ Test_GPIO_Toggle,         10U, 0U },   \
{ AppTask_BSP_Background,    1U,   0U },  \
{ Key_Update,               10U,   0U },  \
{ Sensor_Update,             1U,   0U },  \
{ Encoder_Update,           10U,   0U },  \
{ Test_MotionCmd_Update,    10U,   0U },  \
{ Motion_Update,            10U,   0U },  \
{ Chassis_Update,           10U,   0U },  \
{ Test_MotionCmd_Log,      200U,   0U },  \
```

KEY1（PE4）：左转 90°，统一转向速度上限 3000 cps

KEY2（PE3）：右转 90°，统一转向速度上限 3000 cps

KEY3（PE2）：前进 500 mm，速度 800 cps

KEY4（PE1）：后退 500 mm，速度 800 cps

KEY5（PA15）：立即停止

本测试不再从 USART1 读取 `L/R/f/v/x/0` 控制命令；USART1 仅用于输出启动、拒绝、忙和状态日志。执行动作期间再按 KEY1～KEY4 时，新请求会返回 `BUSY`，不会打断当前动作；KEY5 始终调用 `Motion_Stop()` 立即取消动作并停车。

### 动作库转弯测试说明

`Motion_TurnAngle()`测试要点：

1. 保持车辆静止上电，等待IMU初始化和静止标定完成；若过早按 KEY1/KEY2，动作测试入口会输出 `IMU NOT READY` 并拒绝启动。
2. 第一次悬空车轮按 KEY1，确认左轮目标为负、右轮目标为正；按 KEY2 时方向相反。车轮目标或实际转向方向错误时先检查差速约定、电机和编码器方向；车轮方向正确但日志中的yaw变化方向与命令相反时，再检查`HEADING_IMU_YAW_REVERSE`，不要先改转向参数。
3. 放地面并留出足够空场，分别按 KEY1 和 KEY2。用量角器或地面标线记录实际角度，至少各测3次，分别记录平均角度和重复误差。KEY3/KEY4用于验证500 mm前进/后退，测试时同样留出足够距离。
4. KEY1/KEY2只传入±90°，所有入口统一使用`CONTROL_MOTION_TURN_SPEED_CPS=3000`作为上限。当前比例系数为25.0，90°初始转向命令约为2250 cps；进入±3°容差后停车，连续10个10 ms周期（约100 ms）满足条件才完成，以便继续检查停车后的惯性越界。
5. 若惯性导致越过目标，控制器按角度误差的反方向自动进入500 cps低速回正，并保持低速修正直到重新进入±3°。若回正速度低到电机不动，适当提高`CONTROL_MOTION_TURN_CORRECTION_SPEED_CPS`；若低速回正仍反复跨过目标，则降低该值。

`Test_MotionCmd_Log`字段含义：`st=0/1/2/3`分别为IDLE、RUNNING、DONE、ERROR；`act=0/1/2`分别为NONE、GO_DISTANCE、TURN_ANGLE；`dist=当前/目标毫米`；`yaw`为相对航向角（当前日志取整数）；`tgtL/tgtR`为左右目标cps，越界回正时应看到约`+500/-500`或`-500/+500`；最后四个`out`依次为FL、FR、RL、RR的PWM千分比。动作超过8000 ms未完成会进入`MOTION_ERROR`并停车。

该任务表没有 `LCD_Update()`，也不会激活动作测试专用 LCD 页面。

## 九、测试循迹

```c
{ Test_GPIO_Toggle,        10U, 0U }, /* 运行指示灯 */   \
{ AppTask_BSP_Background,   1U, 0U },                   \
{ Key_Update,              10U, 0U },                   \
{ Sensor_Update,            1U, 0U },                   \
{ Encoder_Update,          10U, 0U },                   \
{ Test_RouteCmd_Update,    10U, 0U },                   \
{ LineTrack_Update,        10U, 0U },                   \
{ Motion_Update,           10U, 0U },                   \
{ Chassis_Update,          10U, 0U },                   \
{ Test_RouteLog,          200U, 0U },                   \
{ LCD_Update,              20U, 0U },                   \
{ OLED_Update,             20U, 0U },                   \
```

### （一）按键操作

KEY1（PE4）：开始循迹。若 IMU 尚未完成初始化和静止标定，启动会被拒绝，并输出 `ROUTE START REJECTED: IMU NOT READY`。

KEY4（PE1）：停止循迹，同时停止 Route 启动的 Motion 动作和底盘。

`Key_Update()` 每 10 ms 生成消抖后的事件，`Test_RouteCmd_Update()` 只处理稳定按下沿，因此按住按键不会重复启动或停止。任务表必须先注册 `Key_Update()`，再注册 `Test_RouteCmd_Update()`。循迹测试时不要同时注册 `Test_Key_Update()`，否则两个任务会共同消费按键事件。

### （二）串口诊断命令

r：复位路线状态

串口不再负责启动、停止或打印路线状态。

### （三）路线 LCD/OLED 调试页

`Test_RouteLog()`保留原函数名，但不再向USART1发送数据；它调用`LcdUi_RouteTestBegin()`和`OledUi_RouteTestBegin()`激活路线调试页。`LCD_Update`负责LCD约200 ms刷新，`OLED_Update`负责OLED按`OLED_UI_UPDATE_PERIOD_MS`刷新；没有注册对应刷新任务的屏幕不会显示该专用页。

LCD第1～10行依次为：标题；路线profile/profile状态/控制权；循迹状态/动作状态/事件确认次数；运行秒数/状态切换次数；线型/灰度掩码；原始误差/滤波误差；循迹模式/连续丢线毫秒；搜索阶段/搜索方向；线速度/转向速度；相对航向角。OLED受6行高度限制，A页显示前半组状态和`RAW/FIL`，B页显示模式、搜索、输出和航向，两页自动切换。

### （四）Basic 丢线恢复测试方法

1. 先悬空车轮按KEY1，确认线路在左时 `RAW<0、OUT T>0`，线路在右时 `RAW>0、OUT T<0`。
2. 正常放在线上和最外侧探头压线时都使用`MODE:TRACK`基础PD；独立`EDGE`模式已经取消，普通循迹输出仍保证`|T|<=L`，内侧轮不会反转。
3. 完全移开黑线：连续2帧后进入 `MODE:SEARCH`，先沿最后线路方向扫描约300ms，再反向；`SCAN P`会增加，扫描时间和速度逐步扩大。
4. 扫描时重新压到黑线：必须连续识别3帧才回到`MODE:TRACK`，用于抑制灰度噪声引起的小幅左右抖动。
5. 搜索超过10秒仍未找到线会安全停车，需要重新按KEY1开始。

所有控制参数只在 `Algorithm/control_config.h` 修改；不要在 Route 或各模块头文件复制一份参数。

## 十、HX711 压力/称重模块串口测试

将任务表临时切换为：

```c
Task_t task_list[] = {
{ Test_GPIO_Toggle,       10U, 0U },
{ AppTask_BSP_Background,  1U, 0U },
{ Sensor_Update,           1U, 0U },
{ Test_HX711_Update,      20U, 0U },
};
```

`Sensor_Update()`负责在 DOUT 就绪时读取 HX711，不能省略。驱动已按空载均值约 `-540045.3`、160.1 g 负载均值约 `-428626.8` 固化 `695.93 counts/g`。上电时称重台必须空载；驱动连续收集 32 个稳定样本自动去皮，10 SPS 下约需 3.2 秒，期间串口保持静默。稳定窗口跨度超过 500 counts 时会重新计数，避免碰动称重台时误记零点。

自动去皮完成后，`Test_HX711_Update()`不读取任何串口命令，只通过 USART1 每 200 ms 输出一行：

```text
WEIGHT=160.1 g
```

串口使用 115200、8-N-1。正常使用不需要发送`t`、`c100`或`p`；这些命令已经从测试任务中删除。若上电时台面已有物体，该物体会被当作零点，因此必须空载上电，等待首次克重输出后再放置物体。

## 十一、E220 无线串口双向通信测试

使用以下最简任务表：

```c
Task_t task_list[] = {
    { Test_GPIO_Toggle,       10U, 0U },
    { AppTask_BSP_Background,  1U, 0U },
    { Test_E220_Link_Update,  10U, 0U },
};
```

两台车可以烧录完全相同的程序。每台车会读取 STM32 芯片唯一编号生成 4 位节点编号，并自动发送以下 ASCII 帧：

```text
E220,1A2B,1
E220,1A2B,2
E220,1A2B,3
```

数字从 1 开始，每成功提交一帧后加 1，发送周期为 1 秒。两台车根据各自芯片唯一编号采用不同的首次发送相位，降低同时发射造成空中碰撞的概率。

`Test_E220_Link_Update()`直接管理本测试的 LCD 和 OLED 页面，不需要再注册`LCD_Update()`、`OLED_Update()`、`Test_LCD_Ascii_Update()`或`Test_OLED_Ascii_Update()`。两块屏幕显示本机节点编号和发送数字、对端节点编号和最新接收数字、有效接收帧数以及链路状态：2.5 秒内收到过有效对端帧显示`LINK:OK`，否则显示`LINK:WAIT`。

两台车的`TX`持续递增、`RX`持续更新且`RX COUNT`增加，能够验证两台车之间的双向无线通信和持续收发稳定性。无线干扰或两端偶然同时发射时允许丢失个别帧；如果长时间保持`LINK:WAIT`，应先检查两端 E220 参数、M0/M1、AUX、交叉接线和各自本地共地，必要时错开时间复位其中一台车。

`AppTask_BSP_Background()`不能省略，它负责推进 E220 的 AUX 忙等待、软件帧队列以及 LCD/OLED 非阻塞驱动。该测试只在`VEHICLE_UART1_LINK_MODE`选择`VEHICLE_UART1_LINK_E220`时收发和显示。

实测结论：两台车烧录同一份程序后，双方均能自动发送递增数字并接收对端数据，LCD/OLED 的`RX`与有效接收帧数持续更新，双向无线通信验证通过。
