# 测试任务注册函数使用方法

> 本文由同名 Word 文档迁移并按当前项目源码校正。Word 原文件保留；后续修改代码时应同步检查本文和 `说明文档.md`。

## 当前默认：五按键串口测试

`APP/app_task_config.h` 已注册最简任务列表：

```c
Task_t task_list[] = {
{ Test_GPIO_Toggle,       10U, 0U },
{ AppTask_BSP_Background,  1U, 0U },
{ Test_Key_Update,        10U, 0U },
};
```

`Test_GPIO_Toggle` 是所有测试任务表都必须保留的常驻运行指示任务；即使要求“最简任务列表”，也不能省略。

`Test_Key_Update()` 自行调用 `BSP_Key_UpdateAll()` 完成 20 ms 消抖，因此按键专项测试不需要注册 `Sensor_Update()`。USART1 使用 115200、8-N-1；普通直连模式下接 USB-TTL，E220 模式下日志从无线链路发出。

上电后先发送：

```text
KEY TEST READY: KEY1=PE4 KEY2=PE3 KEY3=PE2 KEY4=PE1 KEY5=PA15
```

每个按键稳定按下和松开各发送一行：

| 操作 | USART1 输出 |
| --- | --- |
| 按下/松开 KEY1（PE4） | `KEY1 PRESSED (PE4)` / `KEY1 RELEASED (PE4)` |
| 按下/松开 KEY2（PE3） | `KEY2 PRESSED (PE3)` / `KEY2 RELEASED (PE3)` |
| 按下/松开 KEY3（PE2） | `KEY3 PRESSED (PE2)` / `KEY3 RELEASED (PE2)` |
| 按下/松开 KEY4（PE1） | `KEY4 PRESSED (PE1)` / `KEY4 RELEASED (PE1)` |
| 按下/松开 KEY5（PA15） | `KEY5 PRESSED (PA15)` / `KEY5 RELEASED (PA15)` |

PA15 同时是 JTDI 复用脚。当前配置把它改为普通按键输入，因此完整 JTAG 不再可用；PA13/PA14 两线 SWD 下载和调试不受影响。仓库没有开发板原理图，KEY5 暂按与 KEY1～KEY4 相同的内部上拉、低电平按下方式配置，实际有效电平待实板确认。

## 一、电机开环测试（默认 2WD 控制两个前电机；切换为 4WD 后控制四个电机）

```c
Task_t task_list[] = {
{ Test_GPIO_Toggle,        10U,  0U },  \
{ AppTask_BSP_Background,   1U,  0U },  \
{ Encoder_Update,          10U,  0U },  \
{ Test_MotorCmd_Update,    10U,  0U },  \
{ Test_MotorCmd_Log,      200U,  0U },  \
{ Test_DrvEncoder_Log,    200U,  0U },  \
};
```

w：左右电机均设为 +300‰，小车前进

s：左右电机均设为 -300‰，小车后退

a：左侧 -300‰、右侧 +300‰，原地左转

d：左侧 +300‰、右侧 -300‰，原地右转

0：立即停止

{ Test_GPIO_Toggle,        10U,  0U }, \

{ Chassis_Update,          10U,  0U },  \

g：线速度设为 +2000 cps，前进

b：线速度设为 -2000 cps，后退

l：转向速度设为 +1200 cps，原地左转

r：转向速度设为 -1200 cps，原地右转

x 或 0：停止

## 五、灰度传感器与循迹状态调试（此任务表未注册 Motion_Update 和 Chassis_Update，不会实际驱动电机）

```c
{ Test_GPIO_Toggle,       10U,  0U },  \
{ AppTask_BSP_Background,  1U,  0U }, \
{ Sensor_Update,           1U,   0U },   \
{ Encoder_Update,         10U,   0U },   \
{ LineTrack_Update,        10U, 0U },  \
{ Test_LineCmd_Update,     10U, 0U },  \
{ Test_LineCmd_Log,       200U, 0U },  \
```

·  w：将八路传感器全部放在白色区域，采集白色值。

·  b：将八路传感器全部放在黑色区域，采集黑色值。

·  t：根据白色和黑色值生成八路阈值。

·  d：将 8 路阈值统一设为 LINE_DETECT_DEFAULT_THRESHOLD（当前为 2000U）。

·  p：立即打印一次完整数据。

·  k：扫描 I2C1 设备。

·  1 / l / L：请求进入循迹状态（IMU 未就绪时可能被拒绝）。

·  0 或 x：停止循迹状态。

## 六、LCD 测试

### （一）普通测试注册任务

```c
Task_t task_list[] = {
{ Test_GPIO_Toggle,         10U, 0U },   \
{ AppTask_BSP_Background,    1U, 0U },  \
{ Test_LCD_Ascii_Update,     50U, 0U },  \
};
```

注意：Test_LCD_Ascii_Update 是独占屏幕的 ASCII 测试任务，不要与周期性界面任务 LCD_Update 同时注册。

### （二）周期性调用 LCD 注册函数

```c
{ Test_GPIO_Toggle,         10U, 0U },   \
{ AppTask_BSP_Background,    1U, 0U },  \
{ Sensor_Update,             1U,   0U },  \
{ Encoder_Update,           10U,   0U },  \
{ LineTrack_Update,         10U,   0U },  \
{ Chassis_Update,           10U,   0U },  \
{ LCD_Update,             20U,   0U },   \
```

注意：运行时周期性刷新 LCD 时注册 LCD_Update（位置：APP/app_task_config.h）

修改 LCD 仪表盘内容：编辑 APP/lcd_ui.c 中的 LcdUi_ShowDashboard()；更新间隔在 APP/lcd_ui.h 的 LCD_UI_UPDATE_INTERVAL_MS 中修改。

### （三）LCD 显示内容和含义

TRACETRACK DASHBOARD

IMU:OK MAG:HU

R:+1.2 P:-0.5

YAW:+90.3 DEG

LINE:RUN SINGLE

MASK:18 ERR:-250

TGT L:600 R:600

FB L:590 R:610

PWM L:80 R:72

TOF:350 MM

### （四）字段含义

H：磁力计健康

U：当前正在使用磁力计修正

MASK：8 路灰度黑线掩码

ERR：循迹位置误差

TGT：目标编码器速度

FB：编码器实际反馈速度

## 七、OLED 测试

### （一）普通测试注册任务

```c
{ Test_GPIO_Toggle,         10U, 0U },   \
{ AppTask_BSP_Background,    1U, 0U },  \
{ Test_OLED_Ascii_Update,     20U, 0U }, \
```

注意：`OLED_Update()` 是周期性更新 OLED 的任务，不能和 `Test_OLED_Ascii_Update()` 同时使用；`Test_OLED_Ascii_Update()` 只用于测试 OLED 功能。

### （二）周期性调用 OLED 注册函数

```c
{ Test_GPIO_Toggle,         10U, 0U },   \
{ AppTask_BSP_Background,    1U, 0U },  \
{ Sensor_Update,             1U,   0U },  \
{ Encoder_Update,           10U,   0U },  \
{ LineTrack_Update,         10U,   0U },  \
{ Chassis_Update,           10U,   0U },  \
{ OLED_Update,             20U,   0U },   \
```

注意：运行时周期性刷新 OLED 时注册 OLED_Update（位置：APP/app_task_config.h）

修改 OLED 仪表盘内容：编辑 APP/oled_ui.c 中的 OledUi_ShowDashboard()；更新间隔在 APP/oled_ui.h 的 OLED_UI_UPDATE_INTERVAL_MS 中修改。

### （三）OLED 显示内容和含义

R:+1.2 P:-0.5

Y:+90.3 M:HU

LINE:RUN SINGLE

M:18 E:-250

T:600/600 F:590/610

P:80/72 D:350

### （四）字段含义

R/P/Y：Roll、Pitch、Yaw

M:HU：磁力计健康且正在参与修正

LINE：循迹状态和线路类型

M：灰度黑线掩码

E：循迹误差

T：左右目标速度

F：左右反馈速度

P：左右 PWM

D：前方测距，单位 mm

## 九、测试循迹

```c
{ Test_GPIO_Toggle,        10U, 0U }, /* 运行指示灯 */   \
{ AppTask_BSP_Background,   1U, 0U },                   \
{ Sensor_Update,            1U, 0U },                   \
{ Encoder_Update,          10U, 0U },                   \
{ Test_RouteCmd_Update,    10U, 0U },                   \
{ LineTrack_Update,        10U, 0U },                   \
{ Motion_Update,           10U, 0U },                   \
{ Chassis_Update,          10U, 0U },                   \
{ Test_RouteLog,          200U, 0U },                   \
```

### （一）串口命令

l或1：开始循迹

x或0：停止

r：复位路线状态

p：立即打印Route状态

### （二）路线日志任务与 E220 队列

`Test_RouteLog` 在 E220 和普通直连串口模式下均直接注册为 200 ms，不再设置单独的周期宏。E220 忙时完整日志帧会进入软件队列，待 AUX 变高后按顺序重试；5 米以内推荐收发两端使用相同的 `AT+RATE=6`（38.4 kbps）。若长期产生速度仍高于空口发送速度，队列满后仍会返回 `BSP_BUSY`。
