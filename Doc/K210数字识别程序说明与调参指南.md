# K210 数字识别程序说明与调参指南

> 适用项目：送药小车数字 1～8 检测  
> 运行平台：K210 / CanMV  
> 图像分辨率：320×240（QVGA）  
> 模型输入：224×224  
> 文件编码：UTF-8

## 1. 文档目的

这份文档不要求逐行背诵程序，而是帮助调试者掌握下面这条思路：

> 出现什么现象 → 判断是哪一类参数 → 每次改多少 → 观察哪些结果 → 判断是否需要重新训练。

调试时，最重要的是先区分以下三类问题：

1. **画面问题**：曝光、清晰度、运动模糊、数字大小和拍摄角度不合适；
2. **参数问题**：阈值、检测框过滤、ROI、多帧跟踪设置不合适；
3. **模型问题**：某些角度或背景下，错误类别长期比正确类别置信度更高。

如果是画面问题，应先改善相机画面；如果是模型问题，仅靠不断调整阈值通常无法根治，需要补充数据并重新训练。

## 2. 当前基准参数

建议始终保留下面这组基准值。调参后效果变差时，先恢复基准参数，再重新测试。

```python
INFERENCE_MODE = "single"

CONF_THRESHOLD = 0.58
NMS_THRESHOLD = 0.30

MIN_BOX_AREA = 120
MAX_BOX_AREA = 30000
MIN_ASPECT_RATIO = 0.20
MAX_ASPECT_RATIO = 2.00

ROI_LEFT = 0
ROI_TOP = 0
ROI_RIGHT = 320
ROI_BOTTOM = 240

TRACK_CONFIRM_HITS = 2
TRACK_DELETE_MISSES = 3
TRACK_HISTORY = 5

OUTPUT_INTERVAL_MS = 200

VFLIP = False
HORIZONTAL_MIRROR = False
```

### 参数分类

| 类型 | 参数 | 主要作用 |
|---|---|---|
| 模型绑定参数 | `MODEL_PATH`、`LABELS`、`ANCHORS`、模型尺寸等 | 必须与训练导出的模型一致 |
| 单帧检测参数 | 置信度、NMS、面积、宽高比、ROI、识别模式 | 决定当前帧中的检测框能否通过 |
| 多帧稳定参数 | 确认帧数、丢失帧数、投票历史 | 决定结果是否稳定、多久出现和消失 |
| 通信参数 | 串口引脚、波特率、发送周期 | 决定如何向 STM32 发送结果 |
| 画面参数 | 翻转、镜像、摄像头格式和分辨率 | 决定画面方向和输入格式 |

## 3. 不要随意修改的模型绑定参数

以下参数由训练结果和模型结构决定：

```python
MODEL_PATH
LABELS
ANCHORS
classes = 8
img_w = 224
img_h = 224
net_w = 224
net_h = 224
layer_w = 7
layer_h = 7
```

除非重新训练并导出了新模型，否则不要修改。

特别注意：

- `LABELS` 的顺序必须与训练平台导出的类别顺序完全一致；
- `ANCHORS` 必须使用训练该模型时生成的锚框参数；
- 当前模型共有 8 类，对应数字 1～8，所以 `classes=8`；
- 模型路径必须指向实际存在的 `.kmodel` 文件。

修改错误可能导致：

- 数字类别整体错位；
- 模型能运行，但识别结果始终错误；
- 完全检测不到数字；
- KPU 初始化或推理时报错。

## 4. 摄像头初始化与画面方向

典型初始化代码如下：

```python
def init_camera():
    sensor.reset()
    sensor.set_pixformat(sensor.RGB565)
    sensor.set_framesize(sensor.QVGA)
    sensor.set_vflip(VFLIP)
    sensor.set_hmirror(HORIZONTAL_MIRROR)
    sensor.run(1)
    sensor.skip_frames(time=1500)
```

| 代码 | 含义 |
|---|---|
| `sensor.reset()` | 复位并初始化摄像头 |
| `sensor.set_pixformat(sensor.RGB565)` | 使用彩色 RGB565 图像 |
| `sensor.set_framesize(sensor.QVGA)` | 设置分辨率为 320×240 |
| `sensor.set_vflip(VFLIP)` | 控制画面上下翻转 |
| `sensor.set_hmirror(HORIZONTAL_MIRROR)` | 控制画面左右镜像 |
| `sensor.skip_frames(time=1500)` | 等待 1.5 秒，让曝光和画面稳定 |

如果 K210 倒着安装：

```python
VFLIP = True
```

如果屏幕中的左右方向与实际相反：

```python
HORIZONTAL_MIRROR = True
```

画面不清楚、过暗或运动模糊时，应先解决画面问题，不要立刻降低识别阈值。

## 5. 单帧检测参数

### 5.1 置信度阈值 `CONF_THRESHOLD`

```python
CONF_THRESHOLD = 0.58
```

模型会为每个检测结果给出置信度，例如：

```text
digit=5 confidence=0.82
digit=3 confidence=0.61
digit=7 confidence=0.43
```

阈值为 `0.58` 时，前两个结果保留，`0.43` 的结果删除。

#### 正确数字经常检测不到

按小步逐渐降低：

```text
0.58 → 0.55 → 0.52 → 0.50
```

#### 经常把背景识别成数字

按小步逐渐提高：

```text
0.58 → 0.62 → 0.65 → 0.70
```

每次变化建议控制在：

```text
0.03～0.05
```

不要只看某一帧。固定相机和数字，连续观察 10～20 秒，并记录：

- 正确数字出现的比例；
- 是否出现错误数字；
- 正确和错误类别的置信度范围；
- 检测框是否连续存在。

### 5.2 NMS 阈值 `NMS_THRESHOLD`

```python
NMS_THRESHOLD = 0.30
```

NMS 用于删除同一数字周围的重复检测框，通常不需要频繁调整。

| 现象 | 调整建议 |
|---|---|
| 同一个数字经常输出两遍 | 尝试降低到 `0.25` |
| 两个靠得很近的真实数字被合并 | 尝试提高到 `0.35` |
| 没有明显重复框 | 保持 `0.30` |

注意：NMS 阈值不是置信度阈值。它调节的是检测框之间的重叠处理，而不是“模型有多确定”。

### 5.3 检测框面积

```python
MIN_BOX_AREA = 120
MAX_BOX_AREA = 30000
```

程序按照下面的公式计算面积：

```python
area = w * h
```

例如远距离数字的检测框为 `10×10`，面积为 100。因为 `100 < 120`，即使模型已经检测到了，该框仍会被过滤。

远距离小数字经常漏检时，可按下面顺序降低：

```text
120 → 100 → 80 → 60
```

降低 `MIN_BOX_AREA` 后，小杂点和背景误检也更容易通过，所以要同时观察误检数量。

`MAX_BOX_AREA` 用于过滤异常大的框。只有数字距离非常近、几乎占满画面时，才考虑提高该值。

### 5.4 检测框宽高比

```python
MIN_ASPECT_RATIO = 0.20
MAX_ASPECT_RATIO = 2.00
```

计算方法：

```python
ratio = w / h
```

| 框大小 | 宽高比 | 结果 |
|---|---:|---|
| `40×80` | 0.50 | 正常，通过 |
| `8×80` | 0.10 | 太细，过滤 |
| `160×60` | 2.67 | 太宽，过滤 |

当前范围已经比较宽松。只有确认“模型输出了正确框，但被宽高比规则过滤”时再修改，不要优先调整。

### 5.5 ROI 有效识别区域

```python
ROI_LEFT = 0
ROI_TOP = 0
ROI_RIGHT = 320
ROI_BOTTOM = 240
```

当前允许整个 320×240 画面中的结果通过。

程序先识别整幅画面，再判断检测框中心点是否位于 ROI 内。因此缩小 ROI 的主要作用是：

> 删除画面边缘不可能属于数字的误检框。

它不会让中间数字在模型输入中变大。

相机位置固定后，可以尝试：

```python
ROI_LEFT = 30
ROI_TOP = 30
ROI_RIGHT = 290
ROI_BOTTOM = 220
```

ROI 不要紧贴数字可能出现的边缘，应为车身晃动、相机倾斜和转弯留出余量。

### 5.6 单窗口与双窗口模式

```python
INFERENCE_MODE = "single"
```

| 对比项 | `single` 单窗口 | `dual` 双窗口 |
|---|---|---|
| 推理次数 | 每帧 1 次 | 每帧 2 次 |
| FPS | 较高 | 明显降低 |
| 远距离小数字 | 可能偏小 | 在模型输入中更大 |
| 重复框风险 | 较低 | 重叠区域可能重复检测 |
| 适用场景 | 正常比赛距离，优先使用 | 远距离数字确实太小时尝试 |

双窗口示例：

```python
DUAL_WINDOWS = (
    (0, 8, 0),
    (96, 8, 1)
)
```

| 窗口 | 原图横向范围 |
|---|---|
| 左窗口 | X=0～223 |
| 右窗口 | X=96～319 |

两个窗口在 X=96～223 之间重叠，因此同一个数字可能被检测两次，后续必须去重。

只有满足下面条件时才建议尝试 `dual`：

- 数字在画面中确实太小；
- 调低置信度和最小面积后仍漏检；
- 原始画面本身清楚；
- FPS 降低后仍能满足小车任务。

如果原始画面已经模糊，双窗口不会凭空增加图像细节。

## 6. 图像缩放与坐标映射

摄像头画面为 320×240，模型输入为 224×224。如果直接强制缩放，数字会被纵向拉长。

单窗口程序采用等比例缩放加黑边：

```text
320×240 原图
    ↓ 等比例缩放
224×168 图像
    ↓ 上下各添加 28 像素黑边
224×224 模型输入
```

对应代码：

```python
resized = frame.resize(224, 168)
padded = image.Image(size=(224, 224))
padded.draw_image(resized, 0, 28)
```

模型返回的是 224×224 输入中的坐标，因此检测后需要映射回 320×240：

```python
x1 = int(lx1 * 320 / 224)
y1 = int((ly1 - 28) * 240 / 168)
```

因此 STM32 最终接收到的横向位置仍对应 0～319 的原始画面，而不是 0～223。

## 7. 候选检测框的数据结构

一个候选框可以表示为：

```python
candidate = [
    x,
    y,
    w,
    h,
    label,
    confidence,
    preferred_owner
]
```

例如：

```python
[70, 105, 60, 82, "5", 0.84, True]
```

| 下标 | 示例数据 | 含义 |
|---:|---:|---|
| 0 | 70 | 左上角 X |
| 1 | 105 | 左上角 Y |
| 2 | 60 | 框宽度 |
| 3 | 82 | 框高度 |
| 4 | `"5"` | 识别数字 |
| 5 | 0.84 | 置信度 84% |
| 6 | `True` | 是否属于优先窗口 |

中心坐标为：

```python
cx = x + w // 2
cy = y + h // 2
```

上述框的中心约为 `(100, 146)`。

## 8. 重复框判断和过滤

`same_position(a, b)` 主要用三种方法判断两个框是否属于同一个真实数字：

1. 两个框的 IoU 较大；
2. 一个框的大部分区域被另一个框包含；
3. 两个框的中心距离很近。

位置去重阶段故意不比较数字类别。例如同一位置：

```text
左窗口：数字 5，置信度 0.76
右窗口：数字 3，置信度 0.89
```

虽然类别不同，但位置相同，仍先视为同一个物体，再保留更可信的检测，防止同一数字输出两遍。

`valid_box(candidate)` 的过滤顺序为：

```text
宽高大于 0
→ 面积位于允许范围
→ 宽高比正常
→ 中心点位于 ROI
```

任何一项不满足，检测框都会被删除。

## 9. 多帧跟踪与稳定输出

单帧结果容易跳动，例如固定数字 5 时可能得到：

```text
5、5、3、5、5
```

因此程序不会把每一帧直接发送给 STM32，而是为同一位置建立轨迹：

```python
{
    "box": ...,
    "history": ...,
    "consecutive": ...,
    "missed": ...,
    "confirmed": ...
}
```

| 字段 | 含义 |
|---|---|
| `box` | 当前平滑后的检测框 |
| `history` | 最近若干次数字类别和置信度 |
| `consecutive` | 连续检测到的帧数 |
| `missed` | 连续丢失的帧数 |
| `confirmed` | 是否成为稳定结果 |

### 9.1 连续确认帧数

```python
TRACK_CONFIRM_HITS = 2
```

第一次发现目标时：

```text
consecutive=1，confirmed=False
```

下一帧同一位置再次检测到：

```text
consecutive=2，confirmed=True
```

| 现象 | 调整建议 |
|---|---|
| 错误数字一闪而过 | 提高到 `3` |
| 小车运动快，数字出现时间短 | 保持 `2` |
| 希望单帧立即输出 | 不建议改为 `1`，误检会直接发送 |

### 9.2 丢失删除帧数

```python
TRACK_DELETE_MISSES = 3
```

连续丢失 3 帧后才删除轨迹。短暂漏检不会让结果立即消失。

| 现象 | 调整建议 |
|---|---|
| 结果频繁出现又消失 | 提高到 `4` 或 `5` |
| 数字离开后旧结果保留太久 | 降低到 `2` |

该参数调节的是：

```text
抗短暂漏检能力 ↔ 旧结果清除速度
```

### 9.3 投票历史长度

```python
TRACK_HISTORY = 5
```

程序使用最近 5 次识别结果投票。例如：

```text
5: 0.82
5: 0.80
3: 0.76
5: 0.84
3: 0.71
```

数字 5 出现 3 次，数字 3 出现 2 次，最终输出 5。如果次数相同，则比较累计置信度；最终置信度为获胜类别的平均置信度。

| 历史长度 | 稳定性 | 更新速度 |
|---:|---|---|
| 3 | 较低 | 快 |
| 5 | 平衡 | 适中 |
| 7 | 更高 | 较慢 |
| 9 | 很高 | 慢 |

类别来回跳动时可从 `5` 提高到 `7`；镜头切换到新数字后更新太慢时可降低到 `3`。

### 9.4 检测框位置平滑

```python
track["box"] = [
    (old[0] * 2 + detection[0]) // 3,
    ...
]
```

相当于：

```text
新框 = 2/3 × 旧框 + 1/3 × 当前检测框
```

它可以减少中心坐标、宽度和高度的抖动，让 STM32 收到的位置更稳定。

## 10. 从左到右排序

```python
results.sort(key=lambda item: center_xy(item)[0])
```

程序按照中心横坐标从小到大排序。

| 数字 | centerX |
|---:|---:|
| 8 | 36 |
| 5 | 125 |
| 3 | 217 |

最终顺序为：

```text
853
```

STM32 收到的 `items[0]`、`items[1]`、`items[2]` 已经分别对应从左到右第 1、2、3 个数字，不需要再次排序。

## 11. UART 通信

### 11.1 初始化参数和接线

```python
ENABLE_STM32_UART = True
UART_TX_PIN = 6
UART_BAUDRATE = 115200
OUTPUT_INTERVAL_MS = 200
```

```python
fm.register(UART_TX_PIN, fm.fpioa.UART1_TX, force=True)
```

串口格式：

```text
115200，8-N-1
```

当前接线：

```text
K210 IO6 / UART1_TX → STM32 PA3 / USART2_RX
K210 GND            → STM32 GND
```

### 11.2 固定 7 字节帧

```text
AA 55 CMD DATA1 DATA2 DATA3 CHECKSUM
```

| 字节 | 内容 |
|---:|---|
| 0 | `0xAA`，帧头 1 |
| 1 | `0x55`，帧头 2 |
| 2 | 命令字 |
| 3 | 数据 1 |
| 4 | 数据 2 |
| 5 | 数据 3 |
| 6 | 校验和 |

校验和为前 6 个字节相加后保留最低 8 位：

```python
checksum = (
    frame[0] + frame[1] + frame[2] +
    frame[3] + frame[4] + frame[5]
) & 0xFF
```

### 11.3 数字快照

一份识别结果由以下帧组成：

```text
BEGIN
ITEM
ITEM
...
END
```

```python
UART_CMD_SNAPSHOT_BEGIN = 0x10
UART_CMD_SNAPSHOT_ITEM  = 0x11
UART_CMD_SNAPSHOT_END   = 0x12
```

识别到 `853` 时发送：

```text
BEGIN
ITEM：8
ITEM：5
ITEM：3
END
```

共 5 帧，每帧 7 字节，总计 35 字节。因此出现下面的日志是正常的：

```text
UART SNAPSHOT: seq=147 status=1 bytes=35
```

### 11.4 ITEM 数据

```python
index_digit = ((index & 0x0F) << 4) | (digit & 0x0F)
```

高 4 位保存位置序号，低 4 位保存数字。

例如从左到右第 2 个数字是 5：

```text
index = 1
digit = 5
index_digit = 0x15
```

| 字段 | 内容 |
|---|---|
| `DATA1` | 高 4 位为位置序号，低 4 位为数字 |
| `DATA2` | 置信度，范围 0～100 |
| `DATA3` | 压缩后的中心横坐标 |

### 11.5 横坐标压缩

原始横坐标范围为 0～319，一个字节只能保存 0～255，所以 K210 使用：

```python
compressed_x = (center_x * 255 + 159) // 319
```

把 0～319 映射到 0～255，STM32 收到后再恢复到接近 0～319 的坐标。误差很小，足够判断左右位置。

### 11.6 结果状态

```python
UART_RESULT_EMPTY = 0
UART_RESULT_NORMAL = 1
UART_RESULT_AMBIGUOUS = 2
UART_RESULT_OVERFLOW = 3
```

| 状态 | 含义 |
|---:|---|
| 0 | 当前没有稳定数字 |
| 1 | 正常识别到数字 |
| 2 | 预留的结果不明确状态 |
| 3 | 数字数量超过通信缓冲区容量 |

最大结果数量：

```python
UART_MAX_RESULTS = 8
```

检测到超过 8 个数字时，程序发送 `OVERFLOW`，而不是截取前 8 个，以免 STM32 把不完整快照当成正常结果。

### 11.7 发送周期

```python
OUTPUT_INTERVAL_MS = 200
```

表示每 200 ms 发送一次快照，即每秒约 5 次。它不会改变模型推理速度，只改变发送频率。

| 需求 | 建议值 |
|---|---:|
| 需要更快响应 | `100 ms` |
| 当前正常使用 | `200 ms` |
| 日志太密或不需要高频 | `300 ms` |

送药任务通常使用 100～200 ms 即可。

## 12. 主循环执行过程

程序初始化：

```python
lcd.init()
init_camera()
uart = init_uart()
detector = KPU()
detector.load_kmodel(MODEL_PATH)
```

随后初始化 YOLO 参数并进入：

```python
while True:
```

每轮循环执行：

1. 拍摄一帧 320×240 图像；
2. 使用模型检测候选数字；
3. 合并重复框；
4. 过滤面积、宽高比和 ROI 不合格的框；
5. 更新多帧轨迹；
6. 通过投票得到稳定数字；
7. 按中心横坐标从左到右排序；
8. 在屏幕上绘制框、中心和置信度；
9. 每隔指定时间向 STM32 发送一次快照；
10. 在 LCD 上显示画面并回收内存。

## 13. 屏幕信息说明

示例：

```text
DIGITS:853
N:3 single T:0.58
FPS:xx.x
```

| 显示内容 | 含义 |
|---|---|
| `DIGITS:853` | 当前从左到右的稳定数字为 8、5、3 |
| `N:3` | 当前稳定识别到 3 个数字 |
| `single` | 当前使用单窗口模式 |
| `T:0.58` | 当前置信度阈值 |
| `FPS:xx.x` | 每秒处理帧数 |

画面标记通常为：

- 绿色框：稳定检测框；
- 黄色十字：检测框中心；
- 红色文字：数字类别和置信度。

## 14. 故障现象与调参顺序

### 14.1 正确数字经常检测不到

按照以下顺序检查：

1. 确认原始画面清楚，不过暗且没有明显运动模糊；
2. 确认数字大小、拍摄距离和角度与训练图片接近；
3. 把 `CONF_THRESHOLD` 从 `0.58` 降到 `0.55`；
4. 仍漏检时再降到 `0.52`；
5. 把 `MIN_BOX_AREA` 从 `120` 降到 `100` 或 `80`；
6. 检查正确检测框是否被 ROI 删除；
7. 最后再尝试 `dual` 模式；
8. 仍然无效时，补充现场图片并重新训练。

### 14.2 把背景或黑色边框识别成数字

1. 把 `CONF_THRESHOLD` 从 `0.58` 提高到 `0.62`；
2. 必要时提高到 `0.65`；
3. 缩小 ROI，排除不可能出现数字的区域；
4. 适当提高 `MIN_BOX_AREA`，过滤小杂点；
5. 收集容易误识别的现场画面；
6. 将这些负样本或相似背景加入训练数据并重新训练。

### 14.3 数字类别来回跳动

例如：

```text
2、7、2、7、2
```

处理顺序：

1. 确认数字边缘和画面足够清晰；
2. 观察正确类别和错误类别的置信度差距；
3. 保持 `TRACK_CONFIRM_HITS=2`；
4. 将 `TRACK_HISTORY` 从 `5` 提高到 `7`；
5. 如果错误类别长期具有更高置信度，补充相应角度和距离的图片并重新训练。

### 14.4 结果频繁消失又出现

先尝试：

```python
TRACK_DELETE_MISSES = 4
```

如果问题仍然严重，说明底层单帧检测不稳定，应回头检查：

- `CONF_THRESHOLD`；
- `MIN_BOX_AREA`；
- 光照和曝光；
- 数字在画面中的大小；
- 训练数据是否覆盖现场情况。

### 14.5 同一个数字输出两遍

重点检查：

- `NMS_THRESHOLD`；
- `same_position()`；
- 双窗口重叠区域的去重。

可先尝试：

```python
NMS_THRESHOLD = 0.25
```

如果只在 `dual` 模式出现，应观察两个框的中心距离和重叠率，不要通过持续降低置信度解决。

### 14.6 数字离开画面后结果保留太久

降低：

```python
TRACK_DELETE_MISSES = 2
```

如果仍然保留，检查 STM32 是否正确接收并处理 `EMPTY` 快照，避免将旧结果一直缓存。

### 14.7 识别结果出现得太慢

依次判断：

1. 是否使用了 `dual` 模式，导致 FPS 下降；
2. `TRACK_CONFIRM_HITS` 是否设置过大；
3. `TRACK_HISTORY` 是否过长；
4. `OUTPUT_INTERVAL_MS` 是否过大；
5. 模型本身的单帧检测是否经常漏检。

## 15. 快速调参对照表

| 现场现象 | 优先调整 | 调整方向 | 不要先做什么 |
|---|---|---|---|
| 正确数字漏检 | `CONF_THRESHOLD` | 0.58→0.55→0.52 | 一次降到 0.30 |
| 远处小数字被过滤 | `MIN_BOX_AREA` | 120→100→80 | 直接更换所有参数 |
| 背景误检 | `CONF_THRESHOLD`、ROI | 提高阈值、缩小 ROI | 盲目增加跟踪历史 |
| 类别跳动 | `TRACK_HISTORY` | 5→7 | 用 NMS 解决分类问题 |
| 结果频繁闪烁 | `TRACK_DELETE_MISSES` | 3→4 或 5 | 忽略单帧漏检原因 |
| 旧结果清除太慢 | `TRACK_DELETE_MISSES` | 3→2 | 改置信度 |
| 单帧误检一闪而过 | `TRACK_CONFIRM_HITS` | 2→3 | 降为 1 |
| 同一数字出现两个框 | `NMS_THRESHOLD`、去重 | 0.30→0.25 | 调投票历史 |
| 两个近邻数字被合并 | `NMS_THRESHOLD` | 0.30→0.35 | 降低置信度 |
| 远距离目标太小 | `dual` 模式 | 最后尝试 | 原图模糊时强行放大 |
| 错误类别长期高置信度 | 训练数据 | 补图并重新训练 | 继续硬调阈值 |

## 16. 标准调试方法

### 16.1 每次只修改一个参数

错误示例：

```python
CONF_THRESHOLD = 0.45
MIN_BOX_AREA = 50
TRACK_HISTORY = 9
INFERENCE_MODE = "dual"
```

同时改动多个参数后，即使效果变化，也无法判断是哪一个参数造成的。

正确示例：

```text
第 1 轮：只把置信度从 0.58 改为 0.55
第 2 轮：保持 0.55，只把最小面积从 120 改为 100
第 3 轮：恢复无效修改，再单独测试 dual 模式
```

- 同一数字连续观察 10～20 秒；
- 数字 1～8 分别测试；
- 正面、左斜、右斜角度；
- 近距离和正式比赛距离；
- 静止状态和小车缓慢运动状态；

## 17. 何时应该重新训练

出现以下情况时，继续调参数的收益通常很低，应补充数据并重新训练：

- 某个数字在特定角度下长期被识别成另一个数字；
- 错误类别的置信度经常高于正确类别；
- 参数对一个数字有效，却明显破坏其他数字的识别；
- 现场背景、距离或光照与原训练数据差异很大；
- 小车运动时产生的模糊在训练数据中没有覆盖；
- 黑色边框、地面纹理等背景被稳定识别为数字。

补充数据时应重点收集“模型当前最容易错的情况”，例如：

- 不同俯仰角和左右斜角；
- 正式比赛距离；
- 小车运动中略有模糊的图像；
- 明暗不同的现场光照；
- 易混数字，如 2 和 7、3 和 5；
- 会导致误检的真实背景。

重新训练后，必须同步更新模型文件，以及与模型绑定的 `LABELS` 和 `ANCHORS`，再从基准参数开始测试。

## 18. 最终调参口诀

> 漏检先降低置信度和最小面积；误检先提高置信度并缩小 ROI；类别跳动调整投票历史；结果闪烁调整丢失保持；远距离目标太小最后再尝试双窗口；错误类别长期高置信度时补充数据并重新训练。
