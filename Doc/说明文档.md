# TraceTrackCar 项目说明文档

> 文档依据：当前项目源码、`DroneProject.uvprojx`、最近一次 Keil 构建日志，以及 `Doc` 目录中的参数、引脚、测试和注意事项资料。
>
> 核对日期：2026-07-17。
>
> 重要说明：本文区分“代码中已经实现的功能”和“当前默认任务表实际启用的功能”。凡是无法由现有代码或资料确认的内容，均明确标为“待确认”，不作猜测。

## 1. 项目用途和主要功能

TraceTrackCar 是一个以 **STM32F407ZG** 为主控制器的循迹小车项目。项目采用分层结构，将芯片外设、器件驱动、算法和整车应用分开，目标是完成小车底盘控制、灰度循迹、姿态与航向估计、距离测量、路线状态机、显示和视觉模块通信等功能。

代码中已经实现的主要能力如下：

- 支持两轮驱动（2WD）和四轮驱动（4WD）两种硬件配置；当前默认是 **2WD**。
- 电机方向与 PWM 输出控制。
- 最多四路正交编码器采集，以及转速、累计计数和里程换算。
- 左右轮速度闭环 PID 控制。
- 直行指定距离、原地转动指定角度的非阻塞动作接口。
- 8 路灰度传感器采集、黑线判断、位置误差计算和 PD 循迹。
- 支持两种灰度传感器来源：带 MCU 的 I2C 模块和 74HC4051 模拟多路复用模块；当前默认使用 **MCU-I2C 灰度模块**。
- ICM-20948 九轴 IMU 采集、陀螺仪静止标定、姿态融合和航向输出。
- VL53L1X ToF 前向测距。
- 基础循迹路线和 HJduino 路线状态机；当前默认选择 **HJduino 路线**。
- 1.54 英寸 240×240 SPI TFT LCD 和 128×64 I2C OLED 显示。
- USART1 调试串口和 USART2 K210 通信接口。
- K210 侧摄像头示例代码，以及 STM32 侧定长二进制帧解析模块。
- 基于静态任务表的非阻塞协作式调度器，不依赖 RTOS。

### 1.1 当前固件上电后实际做什么

当前 `APP/app_task_config.h` 中注册的是“动作库串口测试”任务，而不是完整循迹任务。实际周期任务为：

| 周期 | 任务 | 作用 |
| --- | --- | --- |
| 1 ms | `AppTask_BSP_Background` | 维护 UART、I2C、SPI 和 LCD/OLED 非阻塞状态机 |
| 1 ms | `Sensor_Update` | 推进 ICM-20948、姿态融合、VL53L1X 和灰度传感器状态机 |
| 10 ms | `Encoder_Update` | 更新编码器增量、速度和累计计数 |
| 10 ms | `Test_MotionCmd_Update` | 从 USART1 接收动作测试命令 |
| 10 ms | `Motion_Update` | 推进直行/转向动作状态机 |
| 10 ms | `Chassis_Update` | 执行速度 PID 并输出电机 PWM |
| 200 ms | `Test_MotionCmd_Log` | 从 USART1 输出动作、航向、目标速度和 PWM 日志 |

因此，当前版本上电后：

- 不会自动启动电机；
- 不会自动进入循迹；
- `LineTrack_Update`、`LCD_Update`、`OLED_Update` 和 `K210_Comm_Update` 当前未注册；
- LCD/OLED 应用层都会请求启动页；OLED 缓冲区可由后台驱动继续发送，而 LCD 启动页绘制作业还需要调用 `LCD_Update` 才会推进。当前两者都不会周期刷新运行仪表盘；
- K210 协议层会初始化，但未注册 `K210_Comm_Update` 时不会周期解析 K210 数据。

## 3. 主要模块及其功能

### 3.1 BSP 板级支持层

| 模块 | 文件 | 功能 |
| --- | --- | --- |
| 统一初始化 | `BSP/bsp_all.c` | 依次初始化 SysTick、GPIO、PWM、编码器、ADC、按键、EXTI、UART、I2C 和 SPI |
| 系统节拍 | `BSP/bsp_systick.*` | 提供毫秒计时和非阻塞超时基础 |
| GPIO | `BSP/bsp_gpio.*` | 电机方向、LCD 控制、IMU 片选、4051 选通、激光使能等普通 GPIO |
| PWM | `BSP/bsp_pwm.*` | TIM8 电机 PWM，以及 TIM13/TIM14 两路 50 Hz 舵机 PWM |
| 编码器 | `BSP/bsp_encoder.*` | TIM1～TIM4 正交编码器计数和周期测速 |
| ADC | `BSP/bsp_adc.*` | ADC1 + DMA，默认启用 PC0/ADC1_IN10 |
| UART | `BSP/bsp_uart.*` | 多路 UART 的 DMA/中断收发；当前启用 USART1 和 USART2 |
| I2C | `BSP/bsp_i2c.*` | 多实例、非阻塞 I2C；当前启用 I2C1，100 kHz |
| SPI | `BSP/bsp_spi.*` | 多实例、DMA SPI；当前 2WD 下启用 SPI1 和 SPI2 |
| 按键/外部中断 | `BSP/bsp_key.*`、`BSP/bsp_exti.*` | 四个低电平按键和通用 EXTI 模板 |

### 3.2 Driver 器件驱动层

| 模块 | 主要文件 | 功能 |
| --- | --- | --- |
| 电机 | `Driver/drv_motor.*` | 将 FL、FR、RL、RR 车轮映射到 PWM 和方向 GPIO，支持方向反转和千分比输出 |
| 编码器 | `Driver/drv_encoder.*` | 将 BSP 编码器映射到四个车轮，换算 cps、mm/s 和累计距离 |
| 灰度传感器 | `drv_gray_sensor.*`、`drv_gray_mcu_i2c.*`、`drv_gray_4051.*` | 在 MCU-I2C 和 4051 两种采集方式之间统一接口 |
| IMU | `Driver/drv_icm20948.*` | SPI2 读写 ICM-20948/AK09916，状态机初始化、采样、滤波和陀螺仪标定 |
| ToF | `Driver/drv_vl53l1x.*` | 通过 I2C1 初始化 VL53L1X 并周期读取、校验和滤波距离 |
| LCD | `Driver/drv_lcd_tft.*` | 240×240 SPI TFT 的非阻塞初始化、填充和文字绘制 |
| OLED | `Driver/drv_oled_i2c.*` | 128×64 I2C OLED 的缓冲区绘图和异步刷新 |
| 测试入口 | `Driver/test.*` | 串口命令、日志以及 GPIO、电机、编码器、传感器、显示等分项测试函数 |

### 3.3 Algorithm 算法层

| 模块 | 作用 |
| --- | --- |
| `pid.*` | 通用 PID，包含输出限幅和积分限幅 |
| `line_detect.*` | 将 8 路灰度值与阈值比较，生成黑线位掩码、线型和加权位置误差 |
| `line_track.*` | 对灰度误差做滤波和 PD 计算，生成线速度与转向速度 |
| `odometer.*` | 根据左右轮累计距离计算整车平均里程 |
| `attitude_estimator.*` | 基于 IMU 的 Roll/Pitch/Yaw 融合、静止偏置修正和磁力计校准 |
| `heading_estimator.*` | 为动作层提供相对航向；当前默认使用融合后的 IMU 航向 |

### 3.4 APP 应用层

| 模块 | 作用 |
| --- | --- |
| `app_all.*` | 统一初始化底盘、里程、姿态、航向、动作、传感器、循迹、显示和 K210 协议层 |
| `scheduler.*` | 遍历静态任务表，按毫秒周期调用各个非阻塞 `Update` 函数 |
| `app_task_config.h` | 当前实际运行的任务列表、任务顺序和周期配置入口 |
| `chassis.*` | 左右差速目标分配和各车轮速度 PID 闭环 |
| `motion_action.*` | 非阻塞直行距离和转动角度动作，并处理完成、容差与超时 |
| `sensor_manager.*` | 统一推进 IMU、姿态、ToF、灰度状态机，并判断 IMU 是否允许小车运动 |
| `line_follow_app.*` | 灰度采集、线检测、路线决策和底盘输出的应用入口 |
| `lcd_ui.*`、`oled_ui.*` | 启动页、运行仪表盘和状态页 |
| `k210_comm.*` | STM32 侧 K210 固定 7 字节帧的收发、校验、缓存和在线判断 |
| `nb_wait.*` | 通用非阻塞等待辅助模块 |

### 3.5 Route 路线层

- `route_manager.*` 根据 `ROUTE_PROFILE_SELECT` 选择路线实现，并协调“循迹控制”和“动作控制”对底盘的所有权。
- `route_profile_basic.*` 只进行普通循迹。
- `route_profile_hjduino.*` 当前实现了：正常循迹、确认右侧环形入口、调用 `Motion_TurnAngle` 进入环形、环内继续循迹和错误状态。
- `route_common.*` 提供交叉、边缘、单线等路线特征判断工具。

### 3.6 K210 侧

- `K210/main.py` 初始化摄像头与 UART1，并示例识别二维码中心和黑线偏移。
- `K210/k210_protocol.py` 负责 K210 侧协议打包。
- 这两份 Python 文件的当前协议与 STM32 的 `APP/k210_comm.*` **不一致**，不能直接认为已经联调可用，详见“已知问题和注意事项”。

## 4. 程序运行流程

### 4.1 上电初始化流程

```text
复位/上电
  ↓
SystemInit()
  ↓
BSP_InitAll(SystemCoreClock)
  ├─ SysTick
  ├─ GPIO / PWM / 编码器 / ADC / 按键 / EXTI
  └─ UART / I2C / SPI
  ↓
Driver_Init()
  ├─ 电机
  ├─ 灰度传感器
  ├─ VL53L1X
  ├─ ICM-20948
  ├─ LCD
  └─ OLED
  ↓
App_Init()
  ├─ 底盘、里程、姿态、航向、动作
  ├─ 传感器管理、循迹和路线
  ├─ LCD/OLED 启动页
  └─ K210 协议状态
  ↓
Scheduler_Init()
  ↓
进入永久主循环
```

### 4.2 主循环与调度

`user/main.c` 的永久循环依次执行：

1. `BSP_UART_TaskAll()`：维护 UART 后台状态。
2. `Scheduler_Run()`：检查静态任务表中每个任务是否到期，到期则调用一次。

这是协作式调度，不是 RTOS：

- 所有任务必须快速返回，不能使用长时间 `delay`、阻塞式等待或无限等待循环。
- 如果某任务执行过久，其后的所有任务都会被推迟。
- 修改任务周期、顺序或启停状态时应改 `APP/app_task_config.h`，不应修改 `scheduler.c`。

### 4.3 当前默认动作测试的数据流

```text
USART1 命令
  ↓ Test_MotionCmd_Update
Motion_GoDistance / Motion_TurnAngle / Motion_Stop
  ↓ Motion_Update
编码器里程 + 融合航向
  ↓
Chassis_SetSpeed
  ↓ Chassis_Update
各车轮 PID
  ↓
Motor_SetAllPermille
  ↓
PWM + 方向 GPIO
```

当前 USART1 动作测试命令：

| 命令 | 动作 |
| --- | --- |
| `f` | 前进 500 mm，命令速度 800 cps |
| `v` | 后退 500 mm，命令速度 800 cps |
| `L` | 原地左转 90°，最大转向命令 1600 cps |
| `R` | 原地右转 90°，最大转向命令 1600 cps |
| `x` 或 `0` | 立即停止当前动作 |

### 4.4 完整循迹流程（代码已实现，但当前未注册）

```text
Sensor_Update
  ↓ 灰度缓存
LineTrack_Update → LineFollow_Update
  ↓
LineDetect_Update（阈值、mask、线型、误差）
  ↓
RouteManager_Update
  ├─ 普通路段：LineTrack_Compute → Chassis_SetSpeed
  └─ 路线动作：Motion_TurnAngle → Motion_Update
  ↓
Chassis_Update
  ↓
电机输出
```

使用当前 HJduino 路线时，`Motion_Update` 也必须保留在任务表中，否则路线状态机发起的转向动作不会推进。

## 5. 硬件连接和使用方法

### 5.1 使用前的基本原则

- 以下引脚以当前源码为准，默认配置为 `VEHICLE_DRIVE_MODE_2WD`。
- 所有外设与 STM32 必须共地。
- 电机电源、电机驱动板型号、驱动板逻辑电平、`STBY/EN/SLP` 有效电平和整车供电电压在现有资料中均未给出，属于 **待确认项**。
- 不要用 STM32 的 3.3 V 引脚直接给电机供电。电机应由与驱动板匹配的独立功率电源供电，并与控制板共地。
- 连接或调整电机、编码器、传感器前先断电；首次烧录和测试时将车轮悬空。

### 5.2 调试与通信接口

| 用途 | STM32 引脚 | 参数/接法 | 当前状态 |
| --- | --- | --- | --- |
| USART1 调试 TX | PA9 | 接 USB-TTL RX | 启用 |
| USART1 调试 RX | PA10 | 接 USB-TTL TX | 启用 |
| USART1 GND | GND | 接 USB-TTL GND | 必须共地 |
| USART2/K210 TX | PA2 | 接 K210 RX | 启用 |
| USART2/K210 RX | PA3 | 接 K210 TX | 启用 |
| SWDIO | PA13 | 接 ST-Link SWDIO | 调试/烧录保留 |
| SWCLK | PA14 | 接 ST-Link SWCLK | 调试/烧录保留 |

USART1 和 USART2 当前均为 **115200、8 数据位、无校验、1 停止位、无硬件流控**。

当前 `K210/main.py` 将 K210 的 IO8 映射为 UART1_TX、IO6 映射为 UART1_RX，因此按该脚本接线时应为：K210 IO8→STM32 PA3、K210 IO6←STM32 PA2、两板 GND 相连。K210 的供电方式和接口电平仍应以具体 K210 模块手册为准。

注意：旧资料中曾出现 USART2 使用 PD5/PD6 的说明，但当前 `BSP/bsp_uart.h` 和 `APP/k210_comm.h` 明确使用 **PA2/PA3**，应以当前源码为准。

### 5.3 电机与编码器

当前默认 2WD 只启用前左 FL 和前右 FR。切换到 4WD 后才启用 RL、RR 及其相关资源。

| 车轮 | PWM | 方向 IN1 | 方向 IN2 | 编码器 A | 编码器 B | 默认状态 |
| --- | --- | --- | --- | --- | --- | --- |
| FL 前左 | PC6 / TIM8_CH1 | PD0 | PD1 | PE9 / TIM1_CH1 | PE11 / TIM1_CH2 | 启用 |
| FR 前右 | PC7 / TIM8_CH2 | PD2 | PD3 | PA0 / TIM2_CH1 | PA1 / TIM2_CH2 | 启用 |
| RL 后左 | PC8 / TIM8_CH3 | PD4 | PD7 | PA6 / TIM3_CH1 | PA7 / TIM3_CH2 | 仅 4WD 启用 |
| RR 后右 | PC9 / TIM8_CH4 | PD8 | PD9 | PB6 / TIM4_CH1 | PB7 / TIM4_CH2 | 仅 4WD 启用 |

驱动板还可能需要 `STBY`、`EN` 或 `SLP` 信号。当前代码没有为这类信号定义独立的电机驱动使能逻辑，必须根据实际驱动板原理图确认是硬件固定到有效电平，还是后续增加 GPIO 控制。

如果小车前进时某个电机反转，优先检查实际 IN1/IN2 接线和 `Driver/drv_motor.h` 中对应的 `MOTOR_*_REVERSE`。如果车轮前进但编码器速度为负，修改 `BSP/bsp_encoder.h` 中相应的 `BSP_ENCODER_CHx_REVERSE`，不要在 PID 或动作代码中到处取反。

### 5.4 灰度传感器

#### 默认：带 MCU 的 I2C 灰度模块

| 信号 | STM32 引脚 | 说明 |
| --- | --- | --- |
| SCL | PB8 | I2C1_SCL，100 kHz |
| SDA | PB9 | I2C1_SDA |
| GND | GND | 必须共地 |

默认 7 位地址为 `0x4C`，代码会扫描 `0x4C`～`0x4F`。模块供电电压、板上是否已有 I2C 上拉电阻，现有资料未明确，接线前需查模块手册。

#### 可选：74HC4051 无 MCU 模拟灰度模块

只有将 `Driver/drv_gray_sensor.h` 中 `GRAY_SENSOR_SOURCE` 改为 `GRAY_SENSOR_SOURCE_4051` 后，应用层才会使用此采集方式。

| 模块信号 | STM32 引脚 | 说明 |
| --- | --- | --- |
| OUT / SIG / AO | PC0 | ADC1_IN10 |
| S0 / A | PD10 | 4051 地址低位 |
| S1 / B | PD11 | 4051 地址中位 |
| S2 / C | PD12 | 4051 地址高位 |
| EN / INH | 待确认 | 资料建议接 GND 以低电平使能，但必须以实际模块手册为准 |

### 5.5 ICM-20948

ICM-20948 固定使用 SPI2：

| ICM-20948 | STM32 | 说明 |
| --- | --- | --- |
| SCLK / SCL | PB13 | SPI2_SCK |
| SDO / AD0 | PB14 | SPI2_MISO |
| SDI / SDA | PB15 | SPI2_MOSI |
| CS / nCS | PE5 | 独立片选，低有效 |
| GND | GND | 共地 |
| INT | 不接 | 当前驱动未使用 |
| FSYNC | 不接 | 当前驱动未使用 |

模块供电电压需按模块规格确认。上电后 IMU 会执行非阻塞初始化和陀螺仪静止标定；标定期间应保持车辆静止。

### 5.6 VL53L1X、OLED 和 I2C1 共线设备

VL53L1X、OLED 和默认 MCU 灰度模块共用 I2C1 的 PB8/PB9：

| 设备 | 地址 | 额外信号 |
| --- | --- | --- |
| VL53L1X | 7 位 `0x29`，代码中 8 位写地址为 `0x52` | 当前 `DRV_VL53L1X_USE_XSHUT=0U`，未使用 XSHUT |
| OLED | 7 位 `0x3C`，备用 `0x3D` | 无 |

### 5.7 TFT LCD

当前 LCD 逻辑会根据驱动模式自动选 SPI 总线：

| 信号 | 2WD 默认 | 4WD | 说明 |
| --- | --- | --- | --- |
| SCL / SCK | PA5 / SPI1_SCK | PB13 / SPI2_SCK | 2WD 下 SPI1 可用；4WD 下 PA6/PA7 被后编码器占用 |
| SDA / MOSI | PA7 / SPI1_MOSI | PB15 / SPI2_MOSI | LCD 为单向写时通常不需要 MISO |
| MISO | PA6 | PB14 | BSP 会配置，实际屏幕是否引出取决于模块 |
| CS | PB12 | PB12 | LCD 独立片选 |
| DC | PC10 | PC10 | 数据/命令选择 |
| BL | PC11 | PC11 | 背光，高电平有效 |
| RES / RST | 待确认 | 待确认 | 当前代码没有独立 LCD 复位 GPIO |

4WD 下 LCD 与 ICM-20948 共用 SPI2，但使用不同 CS；代码包含总线占用和 DMA 状态处理。仍需保证两个设备的接线、片选和 SPI 模式与实际模块一致。

现有 `Doc/宏修改方法.md`（同名 Word 原文件保留）进一步建议：使用 4WD 时关闭 `APP/lcd_ui.h` 中的 `LCD_UI_ENABLE`，不要启用 LCD。虽然当前源码保留了 4WD 下改走 SPI2 的实现，但共享 SPI2 的实车稳定性没有测试报告，因此在完成联合验证前应遵循该保守建议。

### 7.1 推荐方式：Keil μVision

- 目标：`Drone`
- 芯片：`STM32F407ZG`
- 工程使用宏：`USE_STDPERIPH_DRIVER`、`STM32F40_41xxx`

编译步骤：

1. 安装 Keil MDK-ARM，并安装 STM32F4 器件支持包。最近日志使用的是 `Keil.STM32F4xx_DFP.1.0.8`；其他版本能否完全兼容需实际验证。

5. 执行 Rebuild，确认无错误和警告。
6. 不要直接烧录仓库中旧的 `Objects/DroneProject.axf`；应以本次重新编译的时间戳为准。

### 7.2 ST-Link 烧录

1. 断开或关闭电机功率电源，将车轮悬空。
2. 连接 ST-Link：SWDIO→PA13、SWCLK→PA14、GND→GND；建议同时连接目标电压参考和 NRST。目标板供电方式必须按实际开发板说明确认。
3. 在 Keil 的 Debug 设置中选择 ST-Link。当前工程用户配置记录的是 `ST-LINKIII-KEIL_SWO.dll`。
4. 在 Utilities/Flash Download 中确认 STM32F4 1 MB Flash 算法。
5. 执行 Download，将新生成的 `DroneProject.axf` 下载到芯片。
6. 复位并观察串口日志。若 Keil 找不到芯片，依次检查目标供电、共地、SWD 接线、NRST、下载速度和芯片读保护状态。

如果外部工具必须使用 HEX，可在 Keil 的 Output 设置中启用 Create HEX File 后重新构建；当前工程默认没有启用该选项。

### 7.3 GNU Makefile 状态

根目录提供了 `Makefile` 和 GNU 链接脚本，但**当前不建议把它作为可靠的首选构建方式**，原因是脚本仍引用多个当前仓库不存在的源文件，例如：

- `user/bsp_led.c`
- `VL53L1_core/vl53l1_api.c`
- `VL53L1_core/vl53l1_api_calibration.c`
- `VL53L1_platform/vl53l1_platform_init.c`

而当前 Keil 工程引用的 VL53L1X 文件名和文件集合与 Makefile 不同。必须先人工同步 Makefile 源文件列表并完成一次干净构建验证，才能使用 `make` 结果烧录。本文不擅自修改该脚本。

### 7.4 首次通电测试顺序

建议按“先底层、后闭环、最后整车”的顺序测试：

1. **静态检查**：断电检查电源极性、共地、短路、驱动板使能、PWM/方向脚和编码器线。
2. **只接控制电源**：暂不接电机功率电源，烧录程序，确认 MCU 能运行，USART1 有输出。
3. **传感器初始化**：车辆保持静止，等待 IMU 完成陀螺仪标定；检查 I2C/SPI 设备在线情况。
4. **编码器方向**：手动正向转动车轮，确认对应编码器累计值方向正确、左右轮没有串线。
5. **开环电机**：低 PWM、车轮悬空测试每个电机的方向和急停。
6. **速度闭环**：低目标速度测试左右轮反馈和 PID 输出，确认没有反向正反馈。
7. **动作测试**：使用当前默认任务表，通过 USART1 发送 `f`、`v`、`L`、`R`，每次都准备使用 `x` 或 `0` 停止。
8. **灰度标定**：确认 8 路数据顺序和黑白极性，再标定阈值。
9. **循迹测试**：先使用低速、简单闭合轨道；确认循迹任务表、`Motion_Update` 和 `Chassis_Update` 都已注册后再落地运行。
10. **路线与视觉**：在基础循迹稳定后，才测试 HJduino 路线、K210、舵机和激光。

## 8. 已知问题和注意事项

1. **当前默认固件不是自动循迹固件。** `APP/app_task_config.h` 当前注册的是动作测试任务。直接上电不会自动开始循迹，显示仪表盘和 K210 接收任务也未周期注册。

2. **Makefile 与当前源码不一致。** Makefile 引用了不存在的文件；最近能确认成功的是 Keil 工程构建，GNU 构建结果不能在未验证的情况下直接使用。

3. **K210 两端协议不兼容。** STM32 的 `APP/k210_comm.*` 使用固定 7 字节帧 `[AA 55 CMD DATA1 DATA2 DATA3 CHECKSUM]`，校验为前 6 字节累加和；当前 `K210/k210_protocol.py` 使用 `[AA 55 type len payload checksum]` 可变长帧，且校验范围不同。两端代码未经统一前不能直接通信。

4. **K210 功能当前未进入默认调度。** `App_Init()` 只调用 `K210_Comm_Init()`；`K210_Comm_Update` 未在默认任务表注册，因此即使硬件已接好也不会持续解析数据。

5. **HJduino 路线尚未完整。** `Route/route_profile_hjduino.c` 明确指出环形出口检测仍需依据实测赛道特征补充；当前只实现入口确认、转向进入和环内继续循迹。

6. **循迹中的交叉/分支专门处理目前被注释。** `Algorithm/line_track.c` 中交叉保持、边缘急转和分支低速穿越逻辑处于注释状态，当前主要执行丢线处理和普通误差 PD 控制。赛道交叉行为必须实车验证。

7. **灰度标定不持久化。** 运行时黑白采样和阈值生成只存在 RAM；若希望下次上电继续使用，需要人工把实测阈值更新到 `LINE_DETECT_DEFAULT_THRESHOLD_0`～`_7`，或另行实现参数存储。本文未修改源码。

8. **项目资料已按当前源码校正。** 2026-07-17 已同步修正 USART2 PA2/PA3、LCD 的 2WD/4WD SPI 选择、默认 2WD、EXTI_CH1 状态、编码器航向参数、灰度阈值、闭环测试速度、`L/R` 转向 90°和 `OLED_Update` 等内容，并为 4 份 Word 资料建立同名 Markdown 版本。后续每次修改代码时必须同步检查相关 Markdown、Word 原文件和本文。

9. **2WD/4WD 会改变引脚资源。** 2WD 下 SPI1 使用 PA5/PA6/PA7，LCD 默认走 SPI1；4WD 下 PA6/PA7 用于后编码器，LCD 改走 SPI2 并与 ICM-20948 共线。切换驱动模式后必须重新核对全部接线，不能只改宏而不改硬件。

10. **IMU 标定期间必须静止。** `LineFollow_Start()` 会检查 IMU 初始化、数据有效、姿态有效和陀螺仪标定进度；条件不满足时拒绝启动。当前动作测试命令直接调用 `Motion_GoDistance`/`Motion_TurnAngle`，没有同样的入口检查，因此转向测试前仍应主动等待 IMU 准备好。

11. **磁力计会在电机活动时停用修正。** 当前 `ATTITUDE_MAG_DISABLE_WHEN_MOTOR_ACTIVE=1U`，用于降低电机磁干扰。磁标定参数与具体车辆安装位置有关，换车架、换电机或移动 IMU 后需要重新验证。

12. **LCD 缺少独立复位脚定义。** 当前只定义 CS、DC、BL 和 SPI 信号。实际 LCD 模块的 RST 是硬件上拉、与 MCU 复位相连还是需要额外 GPIO，现有资料无法确认。

13. **电机驱动使能和电源规格待确认。** 代码未定义独立 `STBY/EN/SLP` 控制，项目也没有提供电机驱动板原理图、额定电压、电流或保护方式。接电机功率电源前必须按实际硬件确认。

14. **舵机和激光目前主要是底层资源。** PF8/PF9 的 50 Hz PWM 和 PG2 激光使能已配置，但现有 APP/Route 代码中没有完整的目标跟踪、舵机限位和激光安全状态机。不要在未确认机械限位、脉宽和安全措施前驱动实物。

15. **共享总线需要整体测试。** 默认 I2C1 同时服务灰度模块、OLED 和 VL53L1X；4WD 时 SPI2 同时服务 IMU 和 LCD。代码采用非阻塞状态机与总线忙判断，但电气上拉、线长、设备兼容性和高负载下的时序仍必须在实机上验证。

16. **任务不能阻塞。** 调度器没有抢占能力。新增测试、日志或业务函数时，避免长延时、等待硬件完成的 `while` 循环和大量串口同步输出，否则会影响传感器采样、PID 和安全停止响应。

17. **PC13、PE0、舵机和激光的实际外接对象待确认。** 代码只说明它们的逻辑用途，仓库中没有整车原理图或接线图，不能确认开发板上是否已有复用器件或电平转换。

18. **烧录前必须确认正在使用新产物。** `Objects` 和 `build` 中已有历史产物，时间和构建方式不同。每次修改参数或任务表后应执行干净重编译，并核对输出文件时间戳。
