# K210 云台激光循迹项目接手说明

更新日期：2026-07-18  
交接状态：通信链路、黑框识别、舵机闭环和矩形路径均已分别验证；当前阻塞点是“激光落在黑胶带上时无法完成首次锁定”。

## 1. 接手人先看这里

不要先改黑框参数，也不要降低全局红色阈值。当前黑框在夜间固定光源下已经能够锁定；降低全局红色阈值曾造成大量背景亮点被误识别。

接手后的第一项代码任务应当是：让 `laser_detect.py` 的黑胶带局部高亮核心检测能够完成“首次锁定”，而不仅是在已经锁定后用于恢复。

当前代码中的逻辑死结：

```python
def find_black_tape_laser_core(..., current_valid, ...):
    if not current_valid:
        return None

# 调用处又要求 current_valid 为真
if best_blob is None and current_valid:
    best_blob = find_black_tape_laser_core(...)
```

激光模块启动时 `laser_valid=False`，所以局部核心检测永远不能建立第一次锁定。当前日志中的：

```text
laser valid=0 candidate=none output=(160,120) lost=0 max_move=16
```

正是这个问题，不是程序卡死。

推荐修复方向：由 `yuntai_main.py` 把当前路径起点/当前目标点传给 `laser_detect.run()`，在尚未锁定时以目标点作为局部搜索中心，连续确认 3 帧后建立锁定。不能只是删除 `current_valid` 判断，因为默认中心 `(160,120)` 距离当前起点 `(128,94)` 约 41 像素，而局部搜索半径只有 18 像素。

## 2. 当前系统目标

- 进阶目标 1：固定位置 A4 黑胶带矩形，红色激光顺时针沿胶带运行一周。
- 进阶目标 2：A4 靶纸移动、旋转后，重新识别四角并沿边运行。
- 路径必须落在黑胶带上，不能长期走内部白纸。
- STM32 与 K210 使用无阻塞串口通信，不依赖 Keil Debug 窗口观察。

## 3. 硬件与接线

| 设备 | 连接 | 说明 |
|---|---|---|
| K210 第 4 脚 / IO6 / UART1_TX | STM32F103C8T6 PA3 / USART2_RX | 正式通信 |
| K210 GND | STM32 GND | 必须共地 |
| K210 IO6 / TX | USB-TTL RXD | 单独检查 K210 数据 |
| K210 GND | USB-TTL GND | TTL 检查时共地 |
| STM32 PA9 / USART1_TX | USB-TTL RXD | 查看 STM32 状态输出 |

串口参数：115200、8 数据位、无校验、1 停止位（8N1）。

已验证 K210 IO6 能持续发出十六进制帧，STM32 输出中 `checksum=0 format=0 overflow=0`。

## 4. K210 软件结构

SD 卡挂载点：`/sd`，已经通过读写测试。

| 文件 | 作用 | 当前状态 |
|---|---|---|
| `rect_detect.py` | 固定曝光、黑胶带矩形识别、四角排序与稳定锁定 | 夜间参数可锁定 |
| `laser_detect.py` | 红色激光识别、滤波、丢失恢复 | 白纸稳定；黑胶带首次锁定失败 |
| `yuntai_main.py` | 串联黑框锁定、激光识别、矩形路径状态机 | 已跑完一圈，路径位置仍需最终校准 |
| `uart_protocol.py` | UART1/IO6 发目标点和激光点 | 已验证 |
| `main.py` | 本快照中是 Yahboom Welcome 屏代码 | 启动链存在歧义，接手后必须核对 |

注意：本次快照中的 `main.py` 只显示 `Welcome to CanMV`，但之前实际运行日志又出现过 `start yuntai_main`。这说明 SD 卡上的启动文件曾被替换过，或本次压缩包不是最后一次完整快照。接手人必须先核对 K210 当前 SD 卡中的真实 `main.py`，不要直接覆盖。

K210 屏幕只显示 Welcome 并不代表视觉没运行。CanMV IDE 的帧缓冲预览与板载 LCD 是两套输出；程序没有循环调用 `lcd.display(img)` 时，LCD 会停留在启动画面。

## 5. UART 协议

每帧 7 字节：

```text
AA 55 CMD XH XL Y CHECKSUM
```

- `CMD=0x02`：路径目标点。
- `CMD=0x03`：激光点。
- 校验：前 6 字节累加和的低 8 位。
- 无效点使用协议中的无效标志（当前实现会将 Y 置为 `0xFF`）。

STM32 已实际输出：

```text
online=1 frames=... target=(123,96) tvalid=1
laser=(166,128) lvalid=1 checksum=0 format=0 overflow=0
```

## 6. 已确认的参数

### 黑框识别

白天曾成功：固定增益约 16 dB、曝光约 60000 μs、`BLACK_L_MAX=15`。  
夜间当前成功：固定增益 16 dB、曝光 120000 μs、`BLACK_L_MAX=10`。

夜间实测亮度：

- 黑胶带 L：约 3～5。
- A4 内部白纸 L：约 26～27。
- 墙面/背景 L：约 20。

当前 `rect_detect.py` 关键参数：

- 搜索 ROI：`(60, 30, 200, 180)`。
- 稳定确认：5 帧。
- 单帧角点允许移动：5 像素。
- 锚点漂移：7 像素。
- 激光 ROI 外扩：35 像素。
- `find_blobs(..., merge=False, margin=0)`。

最近成功锁定示例：

```text
PATH corners: [(128,94), (202,98), (198,150), (124,146)]
PATH start: 128 94
LASER module start ROI: (87,57,154,132)
```

### 激光识别

白纸上的激光已稳定识别。黑胶带上的激光实测不是纯红色核心，而是“接近白色的高亮核心 + 红色光晕”：

- 核心 RGB 约 `(222～247, 255, 255)`，亮度和 732～757。
- 红色光晕样本如 `(197,174,99)`，红色评分约 121。
- 当前局部核心阈值：亮度和至少 650、光晕红色评分至少 70、局部半径 18。

白色十字停留、同时输出 `candidate=none output=(x,y) lost=10`，表示画面上保留的是旧坐标，并不表示当前仍然检测到激光。

### 路径与舵机

`yuntai_main.py` 当前路径参数：

- 路径步长：4 像素。
- 到达误差：X/Y 各 3 像素。
- 连续到达确认：5 帧。
- 四角向中心缩进：`1/14`（仍是实验值，尚未证明落在胶带中心）。

手动舵机标定值：

| 位置 | 水平脉宽 | 垂直脉宽 |
|---|---:|---:|
| 中位 | 1240 | 1440 |
| 左上 | 1310 | 1380 |
| 右上 | 1130 | 1380 |
| 右下 | 1130 | 1520 |
| 左下 | 1310 | 1520 |

已观察到目标移动到左上时：水平舵机脉宽增加，垂直舵机脉宽减小。

## 7. STM32 工程的重要风险

GitHub 仓库 `Lainey1010/yuntai-` 中检查到的是较旧的开环矩形演示代码，`gimbal_app.c` 主要是舵机测试，仓库中的 `main.c` 也没有完整使用 K210 目标点闭环。

但实机 STM32 已经能打印 `target/tvalid` 和 `laser/lvalid`，说明用户电脑上的 Keil 工程比 GitHub 更新。下一位接手人必须先从用户电脑导出正在烧录的完整 Keil 工程，确认可编译、可烧录后再提交 GitHub。不要根据旧 GitHub 工程覆盖当前单片机程序。

已经实际使用过的闭环调试思路（需在真实 Keil 工程中复核）：更新周期约 100 ms、死区 3 像素、误差除以 8、单次最大修正 4 μs；水平轴符号反向，垂直轴同向。

## 8. SD 卡文件怎样整理

不要继续把所有备份堆在 `/sd` 根目录。电脑上建立如下交接目录，K210 SD 根目录只保留运行所需文件：

```text
K210_云台项目/
├─ 01_当前候选版本/
│  ├─ rect_detect.py
│  ├─ laser_detect.py
│  ├─ yuntai_main.py

├─ 02_稳定回退版本/

│  ├─ laser_detect_before_black_tape_core.py

├─ 03_实验与故障版本/
```

推荐命名：`模块_YYYYMMDD_功能_结果.py`，例如 `laser_20260718_tape_core_first_lock_failed.py`。不要再用无法判断顺序的 `backup(1)`、`最终版2`。

## 9. 下一位接手人的操作顺序

1. 先复制整张 SD 卡到电脑，原卡不改，保存日期快照。
2. 核对实际 `main.py` 是否是启动器还是 Welcome 屏程序。
3. 保存当前 `laser_detect.py`，不要修改黑框阈值。
4. 修改激光模块接口，让 `yuntai_main.py` 把当前目标点作为首次局部搜索种子。
5. 首次锁定要求连续 3 帧，锁定后继续使用现有移动门限和局部恢复。
6. 只用固定曝光测试；晚上继续使用增益 16 dB、曝光 120000 μs作为起点。
7. 先让激光在黑胶带四条边和四角都能稳定 `valid=1`，再恢复舵机运动。
8. 重新验证路径是否在胶带中心；以相机画面和实物照片共同判断，不能只看目标坐标。
9. 测试固定 A4 顺时针一圈，记录用时、掉点次数、连续脱离长度。
10. 最后测试 A4 平移和旋转，并整理用户电脑上的真实 Keil 工程。

## 10. 每次改代码时必须说明

后续任何修改都要同时写清：

- 是否需要拔 SD 卡：如果在电脑直接编辑 SD 文件，需要拔卡；如果在 CanMV IDE 运行一次性补丁写 `/sd`，则不需要拔卡。
- 修改哪个文件、哪一项参数或函数。
- 是否需要完整断电重启：修改 SD 模块后建议完整断电再上电，避免 MicroPython 模块缓存导致重复运行异常。
- 是否需要重新烧录 STM32：只改 K210 `.py` 不需要；改 Keil 工程才需要重新编译下载。
- 验证方法和正确输出是什么。
